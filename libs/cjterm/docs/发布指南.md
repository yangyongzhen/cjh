# cjterm 独立仓库发布指南

cjterm 已自包含（零外部依赖，仅仓颉 std），可作为独立库贡献仓颉生态。
发布到独立仓库的步骤：

## 1. 仓库结构（已就绪）

```
cjterm/
├── src/                    # 源码（22 文件：终端层/渲染/组件/主题）
├── examples/hello/         # 最小示例（cjpm run 可直接跑）
├── README.md               # 库文档（API 概览 + 快速开始 + 跨平台）
├── LICENSE                 # MIT
├── .github/workflows/      # CI 模板（发布时移到仓库根）
└── cjpm.toml               # 包定义（version 0.1.0）
```

## 2. 发布步骤

1. **建独立仓库**：推送到 atomgit（推荐 Cangjie-TPC 组织或自建仓库，命名 `cjterm`）
2. **移动 CI**：把 `libs/cjterm/.github/workflows/build.yml` 移到新仓库根
   `.github/workflows/`（GitHub Actions 只认仓库根）
3. **配 CI 环境**：CI 里需安装仓颉 SDK（官方 apt 源或解压包），参考 workflow 注释
4. **打 tag**：`cjpm.toml` version 已为 0.1.0，发布后 `git tag v0.1.0`
5. **提交中心仓**（可选）：按 pkg.cangjie-lang.cn 的包发布流程提交，
   之后用户可 `cjpm.toml` 里 `cjterm = "0.1.0"` 直接依赖
6. **向 SIG 请求收录**（可选）：Cangjie-TPC / Cangjie-SIG 审核后收录进官方组织

## 3. 与 cjh 主仓库的同步

- cjterm 的源码演进在 cjh 仓库 `libs/cjterm/` 进行，独立仓库作为发布镜像
- 每次 cjterm 有改动：cjh 提交 → 同步到独立仓库 → 打新 tag
- 或反向：独立仓库为源，cjh 用 `path` 依赖指向子模块/子目录

## 4. 维护注意

- 保持零依赖：新增功能只用仓颉 std（stdx 也不引入，保持纯 std）
- 跨平台后端：新平台（如鸿蒙）只需新增一个 `TerminalBackend` 实现 + `@When` 分支
- 渲染层禁止平台分支（ANSI/VT 统一），平台差异全收敛在 backend
