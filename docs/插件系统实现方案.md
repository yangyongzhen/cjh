## 一、现状分析

cjh 已有**半个插件系统**，分散在两处：

### 1.1 技能即 Markdown（`~/.cjh/skills/<name>.md`）

```
---
name: git-helper
description: Git 操作助手
tools:
[
  {"name": "git_status", "description": "查看 git 状态", "command": "git status", "args": {}}
]
---
你是 git 专家...
```

- frontmatter 的 `tools` 段解析为 `DeclarativeTool`（shell 模板 + 参数 schema）
- 正文作为系统提示注入
- `loadSkillTools()`（`main.cj:442`）扫描加载

### 1.2 声明式工具（`DeclarativeTool`，`registry.cj:128`）

```cangjie
public class DeclarativeTool <: CjhTool {
    public let commandTemplate: String        // shell 命令模板，${arg} 占位
    public let argSpecs: HashMap<String, (String, String)>  // 参数 schema
    // execute(): 模板展开 → /bin/bash -c → 返回 stdout/stderr
}
```

### 1.3 工具注册中心（`ToolRegistry`，`registry.cj:50`）

```cangjie
public class ToolRegistry {
    private var tools: HashMap<String, CjhTool>
    public func register(tool: CjhTool): Unit
    public func execute(name: String, args: JsonObject): ToolResult
    public func isReadOnly(name: String): Bool    // V2d 并发分类
}
```

### 1.4 Agent 事件回调点（`loop.cj`，现有）

| 回调 | 触发时机 | 当前用途 |
|------|----------|----------|
| `onDelta(text)` | LLM 流式输出每个 token | TUI 渲染 |
| `onToolStart(name, args)` | 工具开始执行 | TUI 显示 `▶ bash` |
| `onToolResult(name, result)` | 工具执行完毕 | TUI 显示结果摘要 |
| `onThinking()` | 每轮 LLM 调用开始 | 重置计时器 |
| `onTokens(n)` | 每轮 token 用量更新 | TUI 状态行 |

**这些回调点就是事件钩子的天然挂载位。**

## 二、设计目标

### Step 1：`plugin.json` + 插件加载

```
~/.cjh/plugins/
├── web-search/
│   ├── plugin.json          # 元数据：name/version/author/tools
│   └── tools/
│       └── web_search.sh    # 工具实现（shell 脚本）
├── git-helper/
│   ├── plugin.json
│   └── tools/
│       ├── git_status.sh
│       └── git_log.sh
```

- `plugin.json` 声明插件元数据 + 工具列表
- 工具实现 = shell 脚本（ stdin 接收 JSON 参数，stdout 返回结果文本）
- cjh 启动时扫描 `~/.cjh/plugins/*/plugin.json`，动态注册工具
- **与现有技能系统并存**：技能是系统提示注入 + 声明式工具；插件是独立分发的工具包

### Step 2：事件钩子（`on_tool_result` 等）

```cangjie
// 插件可注册的事件钩子
public interface PluginHooks {
    public func onToolResult(toolName: String, content: String): String
    public func onToolStart(toolName: String, args: JsonObject): Unit
    // ... 可扩展
}
```

- 插件 `plugin.json` 声明要监听的事件 + 对应的 shell 脚本
- Agent 在事件回调点调用已注册的钩子
- 钩子可拦截/改写工具结果（如那篇 Pi PR 的 tool-result pruner）

## 三、技术设计

### 3.1 `plugin.json` 格式

```json
{
  "name": "web-search",
  "version": "1.0.0",
  "author": "someone",
  "description": "Web search plugin",
  "tools": [
    {
      "name": "web_search",
      "description": "Search the web and return results",
      "command": "tools/web_search.sh",
      "is_read_only": true,
      "parameters": {
        "type": "object",
        "properties": {
          "query": { "type": "string", "description": "Search query" }
        },
        "required": ["query"]
      }
    }
  ],
  "hooks": {
    "on_tool_result": "hooks/on_tool_result.sh"
  }
}
```

字段说明：

| 字段 | 必填 | 说明 |
|------|------|------|
| `name` | ✅ | 插件名（唯一标识） |
| `version` | ✅ | 语义版本号 |
| `author` | ❌ | 作者 |
| `description` | ❌ | 插件描述 |
| `tools` | ❌ | 工具列表（空数组=纯 hook 插件） |
| `hooks` | ❌ | 事件钩子映射 |

工具字段：

| 字段 | 必填 | 说明 |
|------|------|------|
| `name` | ✅ | 工具名（LLM 调用用） |
| `description` | ✅ | 工具描述（LLM 理解用） |
| `command` | ✅ | 工具实现脚本的相对路径 |
| `is_read_only` | ❌ | 是否纯读（V2d 并发分类），默认 false |
| `parameters` | ✅ | JSON Schema 参数定义 |

### 3.2 工具实现协议（Shell 脚本）

工具实现 = 可执行 shell 脚本，协议如下：

```
输入：stdin 收到 JSON 字符串，包含 LLM 传来的参数
输出：stdout 输出结果文本（回填到消息历史）
退出码：0=成功，非0=失败（is_error=true）
```

示例 `web_search.sh`：

```bash
#!/bin/bash
# stdin: {"query": "仓颉编程语言"}
QUERY=$(cat | jq -r '.query')
curl -s "https://api.search.com/q=${QUERY}" | jq -r '.results[] | "- \(.title): \(.url)"'
```

### 3.3 事件钩子协议

钩子脚本 = 可执行 shell 脚本，协议如下：

```
输入：stdin 收到 JSON 字符串，包含事件数据
输出：stdout 输出改写后的内容（或原内容不变）
退出码：0=正常，非0=钩子失败（忽略，用原内容）
```

`on_tool_result` 事件数据：

```json
{
  "tool": "bash",
  "call_id": "call_abc123",
  "content": "命令输出..."
}
```

钩子输出 = 改写后的 content（替换回消息历史）。

### 3.4 新增类：`PluginManager`

```cangjie
// src/tools/plugin.cj
package cjh.tools

public class PluginManager {
    private let pluginsDir: String
    private var hooks: HashMap<String, String>   // 事件名 → 脚本路径

    public init(pluginsDir: String) {
        this.pluginsDir = pluginsDir
        this.hooks = HashMap<String, String>()
    }

    /**
     * 扫描 pluginsDir/*/plugin.json，加载所有插件
     * - 解析 tools 段，注册为 PluginTool
     * - 解析 hooks 段，记录事件钩子
     */
    public func loadAll(registry: ToolRegistry): Unit

    /**
     * 触发事件钩子，返回改写后的内容
     * 无钩子时原样返回
     */
    public func fireHook(event: String, data: JsonValue): String
}
```

### 3.5 新增类：`PluginTool`

```cangjie
// src/tools/plugin.cj
public class PluginTool <: CjhTool {
    private let name: String
    private let description: String
    private let scriptPath: String        // 工具实现脚本的绝对路径
    private let paramSchema: JsonObject   // JSON Schema
    private let readOnly: Bool            // is_read_only

    public func isReadOnly(): Bool { return this.readOnly }

    public override func spec(): ToolSpec {
        return ToolSpec(this.name, this.description, this.paramSchema)
    }

    public override func execute(args: JsonObject): ToolResult {
        // 1. 构造 stdin JSON = args.toJsonString()
        // 2. 执行 /bin/bash scriptPath，stdin 喂 JSON
        // 3. stdout = 结果文本，exit code = 成功/失败
        // 4. 超时保护（默认 30s）
    }
}
```

### 3.6 Agent 集成事件钩子

`Agent` 类新增 `pluginManager` 字段，在现有事件回调点触发钩子：

```cangjie
// loop.cj - Agent 类
public class Agent {
    private var pluginManager: PluginManager? = None

    public func setPluginManager(pm: PluginManager): Unit {
        this.pluginManager = pm
    }

    // 在工具执行完毕、回填消息历史之前触发
    private func fireToolResultHook(toolName: String, content: String): String {
        match (this.pluginManager) {
            case Some(pm) =>
                var data = JsonObject()
                data.put("tool", JsonString(toolName))
                data.put("content", JsonString(content))
                return pm.fireHook("on_tool_result", data)
            case None => return content
        }
    }
}
```

**调用点**（`loop.cj`，两处 `truncateToolResult` 调用之前）：

```cangjie
// 工具执行完毕 → 触发 on_tool_result 钩子 → 截断+落盘 → 回填
let hookedContent = this.fireToolResultHook(tc.name, result.content)
this.messages.add(ChatMessage("tool",
    truncateToolResult(hookedContent, tc.name, tc.id),
    tc.id, tc.name))
```

## 五、与现有系统的关系

### 5.1 技能 vs 插件

| 维度 | 技能（Skills） | 插件（Plugins） |
|------|----------------|------------------|
| 文件格式 | 单个 `.md` 文件 | 目录（`plugin.json` + 脚本） |
| 系统提示注入 | ✅ 正文作为指令注入 | ❌ 不注入系统提示 |
| 工具定义 | frontmatter `tools` 段 | `plugin.json` `tools` 段 |
| 工具实现 | shell 命令模板（单行） | 独立 shell 脚本（多行复杂逻辑） |
| 事件钩子 | ❌ | ✅ `hooks` 段 |
| 分发 | 手动放 `.md` 文件 | 目录打包，未来支持中心仓 |
| 定位 | 轻量能力扩展 | 完整工具包 |

**两者并存，不冲突。** 技能适合「加几条系统提示 + 简单 shell 工具」；插件适合「完整的工具包 + 事件拦截」。

### 5.2 插件工具 vs 内建工具

- 插件工具和内建工具都注册到同一个 `ToolRegistry`
- LLM 不区分内建工具和插件工具——都是 `tools` 列表里的选项
- 插件工具的 `is_read_only` 参与 V2d 并发分类

## 六、安全考虑

### 6.1 Shell 注入风险

插件工具的 shell 脚本由第三方提供，存在注入风险。

**对策**：
- 工具参数通过 stdin JSON 传递（不拼接到命令行）
- 脚本内部用 `jq -r` 提取参数，不直接 eval
- 在系统提示里告知 LLM「插件工具的参数会通过 stdin 传递」

### 6.2 路径遍历

`plugin.json` 的 `command` 字段如果包含 `../`，可能指向插件目录外的脚本。

**对策**：
- `command` 路径 resolve 后必须仍在插件目录内
- 否则拒绝加载该插件

### 6.3 执行超时

插件脚本如果卡住（如 `curl` 无响应），会阻塞整个 agent 循环。

**对策**：
- `PluginTool.execute()` 内置超时（默认 30s）
- 超时后返回 `ToolResult("工具执行超时", true)`

## 七、实现步骤

### Step 1：plugin.json + 插件加载

1. **`config.cj`**：`CjhConfig` 新增 `pluginsDir`、`enabledPlugins`；`ensureDirs` 创建 `pluginsDir`
2. **`src/tools/plugin.cj`（新文件）**：
   - `PluginTool <: CjhTool`：shell 脚本执行 + stdin JSON 协议 + 超时保护
   - `PluginManager`：扫描 `pluginsDir/*/plugin.json`，解析工具列表和 hooks，注册到 `ToolRegistry`
3. **`main.cj`**：
   - `loadPlugins(pluginsDir, registry, enabledPlugins)`：调用 `PluginManager.loadAll`
   - 在三个入口点（`runCli`/`runJson`/`runTui`）调用 `loadPlugins`
   - `settings.json` 加载 `enabled_plugins` 白名单

### Step 2：事件钩子

4. **`plugin.cj`**：`PluginManager` 新增 `fireHook(event, data)` 方法
   - 查找 `hooks[event]` 对应的脚本路径
   - 执行脚本，stdin 喂事件 JSON，stdout = 改写后内容
5. **`loop.cj`**：
   - `Agent` 新增 `pluginManager` 字段 + `setPluginManager()`
   - 在工具结果回填前触发 `on_tool_result` 钩子
   - 钩子返回的内容经过 `truncateToolResult` 后回填消息历史

### 验证

6. **创建示例插件**：`~/.cjh/plugins/echo-test/plugin.json` + `tools/echo.sh`
   - `echo.sh`：读取 stdin JSON，原样输出
   - 验证 LLM 能调用 `echo` 工具并收到结果
7. **创建 hook 插件**：`~/.cjh/plugins/log-pruner/plugin.json` + `hooks/on_tool_result.sh`
   - `on_tool_result.sh`：工具结果超 1000 字符时截断到 500 字符 + 省略标记
   - 验证钩子能拦截并改写工具结果

## 八、后续能力拓展（Step 3+）

### 8.1 WASM 工具沙箱（Step 3）

Shell 脚本插件的安全边界靠「参数走 stdin」约定，不够强。WASM 插件能提供真正的沙箱：

- 插件用 Rust/Go/AssemblyScript 编写，编译成 `.wasm` 文件
- cjh 嵌入 WASM 运行时（如 Wasmtime），在沙箱里执行插件
- 插件不能直接访问宿主文件系统，只能通过 cjh 提供的 host functions

**好处**：语言无关 + 沙箱安全 + 性能接近原生
**代价**：嵌入 WASM 运行时的工程量 + 仓颉 FFI 适配

### 8.2 MCP 协议支持（Step 3 并行）

[Model Context Protocol](https://modelcontextprotocol.io) 是 Anthropic 主推的开放协议，Cursor / Claude Code / Continue 等均已支持。cjh 应作为 MCP **客户端**接入已有生态。

**架构定位**：MCP 是 V2b 插件系统的**第二种工具来源**，与 shell 插件并存：

```
ToolRegistry
    ↑ register
    ├─ 内建工具（BashTool/ReadTool/...）     ← 编译期
    ├─ Shell 插件（PluginTool）              ← plugin.json + shell 脚本
    └─ MCP 工具（McpTool）                   ← MCP 服务器，JSON-RPC
```

**通信协议**：

| 传输层 | 用途 | 实现 |
|--------|------|------|
| stdio | 本地 MCP 服务器（子进程） | `SubProcess` + JSON-RPC over stdin/stdout |
| SSE / Streamable HTTP | 远程 MCP 服务器 | `HttpClient` + SSE 解析（复用 `SseParser`） |

**生命周期**：

```
cjh 启动
  → 读 settings.json "mcp_servers" 配置
  → 对每个 MCP 服务器：
      1. 建立连接（spawn 子进程 / HTTP 握手）
      2. initialize 握手（协议版本、能力声明）
      3. tools/list → 拿到工具列表
      4. 每个 tool 注册为 McpTool 到 ToolRegistry
  → Agent 运行时，LLM 调用 McpTool
      → McpTool.execute 转发 tools/call 给 MCP 服务器
      → 返回结果

cjh 退出
  → 对每个 MCP 服务器发送 shutdown / 关闭连接
```

**配置格式**（`settings.json`）：

```json
{
  "mcp_servers": {
    "filesystem": {
      "transport": "stdio",
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-filesystem", "/tmp"]
    },
    "github": {
      "transport": "sse",
      "url": "http://localhost:8080/sse"
    }
  }
}
```

**新增类**（`src/tools/mcp.cj`）：

```cangjie
public class McpClient {
    // 建立连接 + initialize 握手 + tools/list
    public func connect(config: McpServerConfig): Unit
    // 转发 tools/call
    public func callTool(name: String, args: JsonObject): ToolResult
    // 关闭连接
    public func disconnect(): Unit
}

public class McpTool <: CjhTool {
    private let client: McpClient
    private let toolName: String
    // execute → client.callTool(toolName, args)
}
```

**与现有系统的关系**：

- MCP 工具和内建/插件工具**统一注册到 `ToolRegistry`**，LLM 不区分来源
- MCP 工具的 `isReadOnly` 从 MCP 服务器的 `annotations.readOnlyHint` 获取
- MCP 的 `resources/*` 和 `prompts/*` 暂不支持（V2b 只接 `tools`）

**实施前提**：

- 仓颉 `SubProcess` 的 stdin/stdout 双向通信（已验证可用）
- JSON-RPC 2.0 消息封装/解析（需新建 `JsonRpc` 辅助类）

### 8.3 中心仓 + `cjh install`（Step 4）

类似 npm registry 或 Cargo crates.io：

- `cjh install web-search` → 从中心仓下载插件包到 `~/.cjh/plugins/`
- `cjh uninstall web-search` → 删除插件
- `cjh plugins list` → 列出已安装插件
- 中心仓后端：AtomGit 仓库 + 简单的索引 API

### 8.4 更多事件钩子（Step 5）

当前 Step 2 只实现 `on_tool_result`。未来可扩展：

| 事件 | 触发时机 | 用途 |
|------|----------|------|
| `on_tool_start` | 工具开始执行 | 日志/审计/权限拦截 |
| `on_delta` | LLM 流式输出 | 输出过滤/改写 |
| `on_compaction` | 上下文压缩前 | 自定义压缩策略 |
| `on_session_end` | 会话结束 | 清理/导出/通知 |

### 8.5 插件间依赖（Step 6）

`plugin.json` 新增 `dependencies` 字段：

```json
{
  "dependencies": ["web-search@1.0.0"]
}
```

`PluginManager.loadAll()` 时按拓扑顺序加载。

### 8.6 插件配置 UI（Step 7）

TUI 里加 `/plugins` 命令：
- 列出已安装插件
- 启用/禁用插件
- 查看插件详情（工具列表、hooks）
