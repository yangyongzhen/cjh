# cjh 模块规划：可复用库拆分路线

> 最后更新：2026-08-21
> 原则：可复用模块独立成库（生态贡献）；agent 业务耦合的留在主项目。
> 拆库时机：趁代码量小、边界清晰时拆，避免后续难拆（每次拆库需 `cjpm clean` 重建）。

## 一、已拆分的独立库（libs/）

| 库 | 内容 | 包名 | 依赖 | 通用价值 |
|---|---|---|---|---|
| **cjterm** | ANSI 控制 + 差分渲染 + termios（纯 libc FFI） | `cjterm` | 零 | ★★★ 任何终端 UI 项目 |
| **cjllm** | 消息模型 + LLM 客户端（OpenAI 协议/SSE/工具调用/mock） | `cjllm` | stdx | ★★★ 任何要调 LLM 的项目 |
| **cjcfg** | 配置系统（settings/auth/会话持久化 + env 覆盖） | `cjcfg` | cjllm（消息模型） | ★★☆ 通用配置+会话 |

主项目依赖：`cjterm` / `cjllm` / `cjcfg`（均 path 依赖）。

## 二、待拆分评估（当前留在主项目）

| 模块 | 内容 | 依赖 | 独立价值 | 决策 |
|---|---|---|---|---|
| **cjagent** | agent 编排（消息循环/工具协议/迭代） | cjllm + cjtools | ★☆☆ 属 agent 业务 | **暂不拆**：拆分只是目录搬移，无外部复用者；等出现第二个 agent 消费者再拆 |
| **cjtools** | 工具注册中心 + 内置工具（bash/read/write） | cjllm（ToolSpec） | ★★☆ 工具协议可复用 | **可选拆**：若做"工具库生态"（如 cj-plugin-*）再拆；当前内置工具与 agent 强耦合 |
| **tui/app.cj** | 对话界面（TuiApp） | cjterm | ★☆☆ 业务界面 | **不拆**：属 cjh 应用层 |

## 三、拆分原则（后续决策依据）

1. **复用价值**：有第二个独立消费者才拆（避免"拆了没人用"）；
2. **依赖边界**：依赖越少越先拆（cjterm 零依赖最先，cjllm 次之）；
3. **时机**：模块稳定 + 代码量 < 2k 行时拆（现在拆成本最低）；
4. **循环依赖**：公共类型抽独立包（cjllm 内的 model 就是这么做的）；
5. **每拆必验**：拆后 `cjpm clean` 重建 + mock/TUI/会话三项回归。

## 四、候选新库（未来按需）

| 库 | 内容 | 触发条件 |
|---|---|---|
| cj-sse | SSE 解析器（从 cjllm 抽出） | 有非 LLM 的 SSE 消费者 |
| cj-ansi | ANSI 控制（从 cjterm 抽出） | cjterm 膨胀时 |
| cj-agent-core | agent 循环（从主项目抽出） | 第二个 agent 应用出现 |

## 五、发布计划

- 目标：发布到仓颉中心仓（pkg.cangjie-lang.cn），按"先 cjterm → cjllm → cjcfg"顺序
- 发布前需：独立 README、版本号、单元测试（@Test）
- 命名约定：`cj*` 前缀（仓颉生态标识），描述用中文+英文

## 六、拆分操作清单（供接手 agent）

```bash
# 1. 建目录 + 复制源码
mkdir -p libs/<name>/src && cp src/<mod>/*.cj libs/<name>/src/

# 2. 改包名（目录内文件）
sed -i 's/package cjh\.<mod>/package <name>/' libs/<name>/src/*.cj

# 3. 处理跨包引用（import cjh.xxx → import <name> 或目标库）
# 4. 建 libs/<name>/cjpm.toml（含 stdx bin-dependencies）
# 5. 主项目 cjpm.toml 加依赖 + 删原 src 目录
# 6. 主项目 import 改名
# 7. cjpm clean && cjpm build（关键！clean 必做）
# 8. 回归：--mock / 会话 / TUI（PTY）
# 9. 更新文档（开发文档 + 进度记录 + 交接文档）
```
