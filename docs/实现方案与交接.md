## 1. 项目是什么

**cjh（Cangjie Harness）**：用华为仓颉语言从零实现的终端交互式编码代理（coding agent）。

用户在终端用自然语言描述任务（"改某文件的某函数"、"跑测试看结果"），agent 理解意图、调用工具（bash/读写文件）、观察结果、迭代完成，全程 TUI 呈现，支持会话持久化。

### 当前状态（2026-08-21）

- ✅ P0 MVP：agent 核心 + 3 工具 + OpenAI 协议 + TUI + mock 验证
- ✅ P1 部分：配置系统（~/.cjh）+ 会话持久化 + cjterm 独立库
- ✅ P1 全部完成：SSE 流式上屏、Anthropic 协议、grep/list_dir 工具、CLI resume、4 用例单测
- 运行验证：mock 工具链端到端通过、TUI 交互通过、会话保存/恢复通过

## 2. 设计起源：参考了什么

本项目的架构灵感来自 **pi（earendil-works/pi）**——一个纯 TypeScript + Bun 的编码 agent harness（约 26 万行，9 个包）。pi 的核心设计被我们平移到了仓颉：

| pi 的设计 | cjh 的对应 |
|---|---|
| agent loop（消息状态机 + 工具调用协议） | `agent/loop.cj` |
| 工具 schema 注册（JSON Schema） | `tools/registry.cj` + `llm/provider.cj` 的 ToolSpec |
| 多提供商 LLM 抽象（ai 包） | `llm/provider.cj` 接口 + openai/mock 实现 |
| 差分渲染 TUI（tui 包） | `cjterm` 库（Screen 差分渲染） |
| 配置目录 ~/.pi/agent（settings/auth 分离） | `~/.cjh/`（settings.json + auth.json 分离） |
| 会话持久化（sessions 目录） | `~/.cjh/sessions/`（JSON 消息历史） |

**为什么能借鉴**：编码 agent 的架构范式是通用的（消息循环 + 工具协议 + LLM 抽象），
pi 用 TS 证明了这套设计的合理性，我们用仓颉重实现——语言不同，架构可平移。
**为什么不是照抄**：仓颉生态无现成 TUI/HTTP-SSE 库，底层全部自研（见 §6 踩坑）；
包划分按仓颉 cjpm 的工程约束重新设计。

## 3. 架构总览

```
配置（config/）→ ~/.cjh/{settings.json, auth.json, sessions/}
    │  env 变量覆盖
终端 TUI（tui/app.cj + cjterm）→ Agent（agent/loop.cj）
                                      │ 消息历史
                                      ▼
                              LlmProvider（llm/）
                                ├─ openai.cj：OpenAI 兼容协议（HTTP + SSE）
                                ├─ mock.cj：离线脚本化 LLM
                                └─ sse.cj：SSE 流解析
                                      │ 工具调用
                                      ▼
                              ToolRegistry（tools/）
                                ├─ bash（executeWithOutput）
                                ├─ read_file（File.readFrom）
                                └─ write_file（File.writeTo）
```

### 消息流（核心循环）

```
ChatMessage(system/user/assistant/tool)
  → provider.chatStream(messages, tools, onDelta)
  → ModelResponse（text 或 ToolCall[]）
  → 有工具调用？执行 ToolRegistry.execute → ToolResult 回填为 tool 消息 → 继续循环
  → 无工具调用？text 为最终答复
```

## 5. 关键模块实现说明

### 5.1 llm/provider.cj — LLM 抽象与流式累加

```cangjie
public interface LlmProvider {
    public func chatStream(messages: ArrayList<ChatMessage>, tools: ArrayList<ToolSpec>,
        onDelta: (String) -> Unit): ModelResponse
}
```

- `StreamAccumulator`：处理 SSE 帧，累积文本增量 + **工具调用分片**（tool_calls 可能分多个 chunk，按 id/name/arguments 拼接）
- `ToolSpec`：JSON Schema 格式（type=function + function{name,description,parameters}）

### 5.2 llm/openai.cj — OpenAI 兼容协议

- 请求：`HttpRequestBuilder().post().url(baseUrl).header("Authorization","Bearer key").body(json)`
- 响应：`ClientBuilder().build().send(req)` → `resp.body` 是 InputStream → SseParser 逐块解析
- 错误：非 200 读取错误体抛 LlmException

### 5.3 llm/sse.cj — SSE 解析

- 逐块读 InputStream（8192 缓冲），按 `\n\n` / `\r\n\r\n` 切分事件
- 处理跨块边界（pending 缓冲）
- data 行拼接（多行 data 用 \n 连接）

### 5.4 agent/loop.cj — 主循环

- 构造时注入 system prompt
- `run(userInput)`：追加 user 消息 → 循环（≤maxIterations）→ 解析响应 → 工具调用执行回填 / 文本返回
- 事件回调（onDelta/onToolStart/onToolResult/onAssistantText）供 TUI/CLI 展示
- `loadHistory()`：恢复会话时注入历史（跳过 system）

### 5.5 tools/ — 工具系统

- `CjhTool` 接口：`spec(): ToolSpec` + `execute(args): ToolResult`
- `ToolRegistry`：注册/分发/异常捕获（工具内异常转 ToolResult(isError=true)）
- `JsonSchema` 辅助：构造 JSON Schema（object/str）
- bash 用 `executeWithOutput("/bin/bash", ["-c", cmd])` 捕获 stdout/stderr

### 5.6 config/ — 配置系统

优先级：**环境变量 > auth.json/settings.json > 内置默认**

```
~/.cjh/（CJH_CONFIG_DIR 可覆盖）
├── settings.json    # base_url / model / max_iterations / system_prompt
├── auth.json        # api_key（兼容 openai_api_key/deepseek_api_key/dashscope_api_key 字段）
└── sessions/        # 会话 JSON
```

- `env_ffi.cj`：getenv FFI 封装（foreign 函数名必须与 libc 符号一致，不能改名！）
- 无 key 时抛 LlmException，提示 auth.json 路径或环境变量

### 5.7 config/session.cj — 会话持久化

- 格式：`{"id","created","messages":[{role,content,tool_call_id?,name?}]}`
- `save(messages)` → 会话 ID（`s<秒>.<毫秒>`）；`load(id)` → 消息历史
- `list()` → (id, 首条 user 消息摘要)，用 `Directory.walk` 遍历
- 会话 ID 用 `DateTime.now().toUnixTimeStamp()`（Duration）转秒.毫秒

### 5.8 cjterm（libs/cjterm/）— 独立终端 UI 库

- `ansi.cj`：ANSI 控制（256 色/光标/清屏），ESC 用 `Rune(27).toString()`
- `screen.cj`：差分渲染（期望网格 + 逐行 diff，只输出变化行）
- `term.cj`：**纯 libc FFI** termios（见 §6.6）
- 主项目 `[dependencies] cjterm = { path = "./libs/cjterm" }`

### 5.9 tui/app.cj — 对话界面

- 布局：标题行 + 输出区（滚动）+ 输入行
- 事件循环：非阻塞按键（5ms 轮询）→ 处理（Ctrl-C 退出/Enter 提交/退格/可打印字符）
- onSubmit 回调 → agent.run → appendOutput（ANSI 着色：工具黄/结果灰/答复绿）
- 会话恢复提示、保存提示（--resume ID）

## 6. 踩坑记录（接手者必读，全部实测）

### 6.1 仓颉语法层

| 坑 | 解法 |
|---|---|
| `type` 是关键字 | 参数改名或反引号 |
| 顶层变量禁 static | 类静态成员 |
| `LibC.malloc` 返回 Option | `if let Some(p) <- malloc(...)` |
| if-let 语法 | `if (let Some(x) <- opt)`；多条件用 `&&` |
| String 迭代 | `for (cp in s)` 得 UInt32 码点；`Rune(cp)` 还原字符 |
| String 下标 | `s[i]` 返回 Byte（UTF-8 字节）；切片 `s[a..b]` |
| 按位取反 | 一元 `!`（非 `~`） |
| lambda 多参 | `{ a, b => ... }` 无括号；空 `{ => }` |
| lambda 捕获可变局部 | 禁止，用类静态成员中转 |
| Option 默认值 | `a ?? b`（无 getOrElse） |
| 数组构造 | 无 `[a,b]` 字面量；`Array(n, repeat: v)` 或 ArrayList |
| JsonKind 比较 | 必须 `match (v.kind())`，不能 `==`/`!=` |
| Byte 字面量 | `10u8`（无 toByte） |
| import 顺序 | 全部 import 必须在声明前 |
| Unicode 转义 | 无 `\u001B`；用 `Rune(27).toString()` |

### 6.2 cjpm 工程层（重要！）

| 坑 | 解法 |
|---|---|
| **子包漏链** | 主项目 exe 不自动链 src/ 下子包 staticlib → **link-option 留空**，靠 cjpm 自动；新增子包后 `cjpm clean` |
| **link-option 覆盖子包链** | 手写 link-option 会挤掉子包/stdx 自动链接 → 只在不干扰时用 |
| 子包包名 | `src/llm/` 内须 `package cjh.llm`（点分包名） |
| 包间循环依赖 | 抽公共类型到独立包（cjh.model） |
| 依赖库 C 符号未链 | 依赖库的 link-option 排在主项目 -L 前 → 依赖库内部不要留 -l，主项目统一（本方案已用纯 FFI 规避） |

### 6.3 链接与 FFI

| 坑 | 解法 |
|---|---|
| **foreign 函数改名后 undefined** | foreign 函数名必须与 C 符号一致（`getenv` 匹配 libc），不能随意改名 |
| 类内 static foreign 语法错 | foreign 顶层声明 + 类静态方法包装 |
| g_signal_connect 是宏 | 用 `g_signal_connect_data`（tauri_cj 经验，cjh 未用） |

### 6.4 stdx / std 库 API

| 坑 | 解法 |
|---|---|
| 无 std.json | 用 stdx.encoding.json（JsonValue.fromStr / toJsonString） |
| Client 构造 | `ClientBuilder().build()`（无 `Client()`） |
| ArrayList 无 map | for 循环 |
| Directory.list 不存在 | `Directory.walk(path, cb)` |
| DateTime 无 toUnixTimestamp | `toUnixTimeStamp(): Duration` |
| File.readString 不存在 | `String.fromUtf8(File.readFrom(path))` |
| ConsoleReader 无公开构造 | `getStdIn().read(buf)` 流式读 |
| 复合 if-let 分隔 | `&&`（非逗号/分号） |

### 6.5 运行时

| 坑 | 解法 |
|---|---|
| 产物缺动态库 | LD_LIBRARY_PATH 加 stdx + cangjie runtime + third_party/llvm/lib |
| 字节截断破坏 UTF-8 | 迭代码点截断，不按字节切片 |

### 6.6 termios 纯 FFI 布局（cjterm）

Linux x86_64 termios 60 字节：
```
c_iflag(0,4) c_oflag(4) c_cflag(8) c_lflag(12) c_line(16) c_cc[32](17..48) ispeed(48) ospeed(52)
```
- 原始模式：清 lflag 的 ICANON|ECHO|ISIG|IEXTEN，清 iflag 的 IXON|ICRNL|BRKINT|INPCK|ISTRIP
- 按键：read(fd, buf, 1)；就绪检测：select(1, fds, ..., timeout=0)
- 尺寸：ioctl(TIOCGWINSZ=0x5413) → winsize{row,col}
