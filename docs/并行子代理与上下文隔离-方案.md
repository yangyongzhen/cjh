> 范式：借鉴 OpenAI Swarm 的 handoff 模型与 Linux fork/进程组语义，落地为 cjh 的 Agent 树。

## 1. 一句话概念模型

> **Agent 树 = 进程树**：父代理在轮内 fork 出 N 个受限子代理（权限单调收窄、深度 1、并发有上限），
> 各自跑独立对话，父 `wait()` 收结构化结果，全程在 TUI/Web 以树状呈现，中断信号杀整棵树。

### 四个不变量（后续所有相关 PR 的评审标尺）

1. **权限单调性**：子代理的有效权限 ⊆ 父代理（capability 继承 + explore 结构化只读 + 剥离 task）。
2. **上下文单向流**：数据经「简报 ↓ / 结论 ↑」两道窄门，子过程不回流父历史。
3. **可观测**：树上每个节点的事件在 TUI/Web 可见、可审批、可中断。
4. **有界资源**：并发度、迭代数、token、时间都有上限，超限=结构化失败而非挂死。

## 3. 范式映射

| Linux fork / Swarm | cjh 对应物 | 现状 |
|---|---|---|
| `fork()` | 一批 tool_calls 里的多个 `task` 调用 | ✅ 已可并发 |
| COW（写时复制） | 子代理不复制父历史，拿「任务简报 + 上下文块」；首次写才生成自己的 messages | ✅（更激进：根本不共享页） |
| `wait()` + exit status | `TaskSpawnResult` | ⚠️ 缺 status / filesTouched |
| `ulimit` | max_iterations=5 | ⚠️ 缺 token/时间/并发上限 |
| 进程树 / 进程组 | Agent 树 + TUI/Web 树状呈现 | ❌ G5 |
| 信号 / SIGKILL | Ctrl+C / Web cancel 传播整棵树 | ❌ 未实现 |
| seccomp / capabilities | 权限单调继承：子 ⊆ 父 | ❌ 反着来（G1/G2） |
| fork 炸弹防护 | 深度 1：子 registry 剥离 task | ❌（G3） |

**坚持的设计立场**：上下文隔离比 COW 更彻底——父历史一个字节都不给子代理。
不引入「共享父历史尾部」选项，否则压缩/审批/中断都要考虑共享态，G 系列问题翻倍。

## 4. 隔离边界

- **隔离**：messages（已有）、todos（子 registry 剥离 todowrite，5 轮迭代内无价值）、
  spill 目录 `spillDir/<sessionId>/sub-<label>/`（G6）、bash 会话（现状 Mutex 串行可接受，文档注明）。
- **共享（只读）**：provider 连接、ToolRegistry 工具实例（线程安全已按每调用状态处理）、sessionStore（不写）。
- **显式传递**：任务简报（§5）。

## 5. 任务简报（决策 D1：简报 + 上下文块）

fork 时子代理收到的 = **子任务 prompt + 父代理自动附带的上下文块**，构成：

```
<子任务 prompt>

--- 父会话上下文（父代理自动附带，LLM 不可编辑）---
- 本会话已触碰文件：<touched paths 列表，去重>
- 会话摘要：<复用 Agent.summarizeForMemory()>
```

- 上下文块由 spawnFn 闭包在父 Agent 上现取（entries.cj 中 agent 先于 TaskTool 注册，闭包可捕获）；
  LLM 只写 prompt，不自己挑上下文（防夹带膨胀，也防偷懒漏带）。
- 块大小上限 ~1500 字符（`truncateUtf8` 截断），避免简报本身成为新的 token 爆点。
- `touched paths` 来源：Agent 从工具调用提取（复用 extractResourceAccess 的 path 提取逻辑）累计。

## 6. 权限与审批（决策 D2/D3）

- **G1 修复**：spawnSubagent 透传父 `config.capability`。
- **G2 修复（结构化强制）**：explore 构造只读 registry 视图——仅注册 `isReadOnly()==true` 的工具，
  写工具物理不可达，不依赖 prompt 自觉；bash 不进入 explore 视图（先从简，只读调查够用）。
  worker 全量工具但受 capability 闸门约束。
- **G3 修复（深度 1）**：子 registry 一律剥离 `task` 与 `todowrite`（连带修 G4）。
- **G5 修复（审批传播）**：worker 触发审批时，回调打 `[task:label]` 前缀走父审批通道
  （TUI 弹窗 / WS approval_request 复用现有 request_id 多路复用）；超时=拒绝（沿用现有语义）。

## 7. 并发、回传与中断

- **并发上限**：`Semaphore(maxConcurrentSubagents)`，默认 4（settings 可配），超出排队。
- **结构化结果**：`TaskSpawnResult` 扩为
  `status(ok|failed|cancelled|budget_exceeded) + text + iterations + tokens + filesTouched + transcriptPath`。
  完整转录落盘（可回看），回父上下文只有结论（窄门）。
- **token 归账**：子代理 tokens 计入父 RunSummary，回合总结条展示全树消耗。
- **中断传播**：父 interruptFlag → 遍历子代理同置位，子提前退出返回 `cancelled`；Web cancel 同路径。
- **线程纪律**：子代理线程 try/catch 全包（仓颉 spawn 内未捕获异常退出码为 0 的已知坑），
  失败转 `status=failed` 而非静默。

## 8. TUI / Web 呈现

- **TUI**：task 工具结果渲染树形前缀（`├─ [explore:找配置]`）；子事件经回调加前缀汇入主流；
  Tasks 面板不加树（保持简单，树在消息流里呈现）。
- **Web 协议 v5**：turn 级帧加可选 `agent_id`/`agent_label`；approval_request 加 agent 标签；
  能力清单按「帧清单推导」惯例自动出新 feature 位（见 web/capabilities.cj 的不虚报原则）。

## 10. 风险登记

1. **token 成本放大**：N 路并发 = N 份独立 prompt → 并发上限 + 预算 + 总结条全树归账兜底。
2. **审批多路并发**：多个 worker 同时要审批 → TUI 顺序弹、WS 靠 request_id 多路复用（已有），
   UI 需队列化 modal 防互相覆盖。
3. **差分渲染压力**：子事件前缀汇入加大 TUI 重绘频率 → pty 测试矩阵必须扩。
4. **仓颉线程坑**：spawn 未捕获异常退出码 0 → 子线程 try/catch 全包。
5. **bash 串行假象**：并发 worker 的 bash 实际串行（Mutex）→ 方案文档明示，避免误报。
