# 13MB 塞进你的应用：我用一个仓颉二进制，给两款软件装上了"AI 大脑"

最近半年我一直在折腾一件事：给自己的应用接 AI。

听起来平平无奇？"调个大模型 API 不就行了。"——你真上手就会发现，你要的从来不是"调一次 API"，而是一整套 Agent 能力：多轮会话、工具调用（读写文件、跑命令、搜网页）、上下文超长自动压缩、危险操作的审批拦截、MCP 插件生态……

这些东西拼起来，就是一个完整的 Agent 框架。自己造？我劝你先看看日历。

所以我换了个思路：**有没有一个现成的 Agent 引擎，小到可以直接"塞"进我的应用里？**

这就是今天要安利的主角——[cjh](https://atomgit.com/qq8864/cjh)，一个用仓颉语言写的终端 Coding Agent。

![cjh 终端界面](https://raw.gitcode.com/qq8864/cjh/raw/main/site/assets/cjh.png)

## 一、先说体积：小到离谱，这是我选它的第一原因

内嵌场景对体积和依赖是零容忍的。cjh 的答卷：

| 平台 | 产物 | 体积 | 依赖 |
|------|------|------|------|
| Linux | 静态单文件 | **18MB** | 零（仅系统 libc） |
| Windows | 单 exe | **13.4MB** | 可选：+4 个 DLL 自包含 |

对比一下常见方案：Node 系 agent 拉下来 `node_modules` 轻松 200MB+；Python 方案还得配虚拟环境。cjh 是**仓颉原生静态编译**，一个文件下载、`chmod +x`、跑起来，三步完事，宿主应用连运行时都不用装。

我特意看了下它 strip 之后的 Windows exe——13.4MB，比你随手截一张高清截图存出来大不了多少。这个体积放进安装包里，用户基本无感。

## 二、它不是"API 壳"，是个五脏俱全的 Agent

很多人一听"集成 agent"就以为是包一层 chat 接口。cjh 给的是全套：

- **15 个内置工具**：bash、文件读写编辑、grep/glob/ast_grep、联网搜索抓取
- **并行子代理**：一个任务自动拆给多个子 agent 并发调查，带并发/token/超时边界管控
- **自动 Compaction**：上下文超长后台自动摘要压缩，长会话不爆
- **三域 Capability 安全模型**：命令/工具/资源白名单 + 危险操作审批链
- **MCP 协议**：标准 MCP 服务器即插即用

## 三、怎么内嵌：三种姿势，我选了最省心的

把 Agent 引擎接进自己的应用，官方集成指南里把三条路摆得很清楚：

| 路径 | 结论 |
|------|------|
| 进程内嵌成库 | ❌ cjh 是可执行根包，仓颉不允许被导入；而且 agent 崩溃会连累 UI |
| 自己写 mini-agent | ❌ 丢掉工具/审批/压缩/MCP 整个生态，得不偿失 |
| **进程外 `cjh web` 子进程** | ✅ REST + WebSocket，崩溃隔离，可独立升级 |

进程外方案的好处一句话说透：**你的应用和 AI 引擎之间只隔一个 localhost 端口**。agent 崩了？宿主应用毫发无伤，重拉一个就行；cjh 出新版？换个二进制，宿主一行代码不用动。

宿主对子进程的生命周期管理，官方沉淀了**六条语义**，我原文照抄没有踩坑：

1. 就绪判据只有一条：`GET /api/health` 返回 200（100ms × 10s 等待，超时不算成功）
2. 复用优先：端口上已有活的 cjh 就复用，退出时也不动它
3. 只收自己拉起的进程（记 `owned` 标志）
4. Windows 下拉起必须用 `launchHidden`，不然 GUI 应用带个黑窗口
5. 自己拉起的一律 `--bind 127.0.0.1`——安全第一
6. 收尾用守护线程兜底，收 5 轮防"秒关窗口"抢跑

## 四、三步接入（代码可直接抄）

### Step 1：拉起 + 等就绪

```bash
# 就一行：绑回环、带 token、后台起
cjh web --port 8765 --token my-secret --bind 127.0.0.1
```

```cangjie
// 宿主侧（仓颉示例，ai-chat 的真实实现就 33KB 托管代码）
// 轮询 GET /api/health 直到 200，超时不标记成功
```

### Step 2：REST 拿元数据

```bash
# 会话列表 / 模型列表 / 能力自述（客户端按 capabilities 决定能发什么帧）
curl http://127.0.0.1:8765/api/capabilities
curl http://127.0.0.1:8765/api/sessions
```

`/api/capabilities` 这个设计我很喜欢：服务端自述"我能处理什么帧"，客户端不用试错。

### Step 3：WebSocket 流式对话

连上 WS 后发 `ChatRequest`，然后收流式帧。这里有个**头号坑**，官方指南单独标红：

> `delta` 帧自带 `text` 裸字段——先按"包装体 `{data:...}`"去 `JSON.parse` 会抛异常。解包顺序固定：**`p.type` → `p.text` → `p.data` → 字符串 parse**。三个集成方踩过同一个坑，别再踩了。

收到的帧依次是 `tool_start`（要调工具了）→ `tool_result`（工具结果）→ `delta`（流式文本）→ `done`（回合结束）。前端拿到 `delta` 直接往界面上追加就行，打字机效果白送。

## 五、两款真实落地的软件

光说不练假把式。cjh 目前已经跑在两款真实软件里（都在 cj-tauri 仓有完整介绍）：

**ai-chat** —— 一个 AI 客户端。它对接 cjh 的宿主代码只有 33KB，直接抄就能用：拉起子进程、WS 对话、审批转发、工具状态展示，全齐。

**cjnote** —— 一个笔记本应用。笔记软件里嵌 AI 是最自然的场景：选中一段笔记问"帮我总结"，或者让 agent 直接翻你的笔记库做检索整理——这就是把 cjh 当"本地大脑"用。
