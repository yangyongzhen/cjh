# 设计：仓颉内置知识层（Cangjie Knowledge Layer）

> 状态：**待评审**（评审通过后再动代码）
> 版本：草案 v1（2026-09-12）
> 关联代码：`src/skills.cj`（技能 / 项目记忆）、`src/tools/`（工具注册与契约）、`src/tools/trust.cj`（信任列表）
> 一句话：给 cjh 加一层**随包分发、离线可用、按需检索**的仓颉知识（语言手册 / API / 示例 / 工程流程 / 资源地图），并让它与已有的"技能""项目记忆"两条通道协同，而不是另起一套。

## 1. 背景

cjh 是仓颉写的 agent harness，对仓颉语言与工具链理应最"懂行"。但现状是：**有记忆、有技能，没有知识层**。

- **项目记忆**（`src/skills.cj:399` / `:414`）：会话结束由模型摘要成一段话写入 `memoryDir/<project>.md`，下次启动注入。它是"会话结论"，**不可按主题检索**。
- **技能**（`src/skills.cj:222 loadSkills`）：`~/.cjh/skills/<name>.md`，frontmatter 声明 `name/description/tools`，启动时**把正文整体拼接注入 system prompt**（`:219-220`）。适合放短指令，不适合放语料。
- **联网**：`WebFetchTool` / `WebSearchTool` 能查官网，但慢、依赖网络、离线不可用，且每次都要重新检索、无法沉淀。
- **工具结果截断回溯**（`src/skills.cj:447-450`）：超长结果头尾保留、中间落盘并提示用 `read_file` 回读——这条既有约定恰好是"片段检索 + 按需读全文"的现成落地方式。

于是问"仓颉问题"目前只有两条路：靠模型自身记忆（可能过时或幻觉），或联网现查（慢且不稳）。本设计补第三条：**本地、离线、可检索、可更新的仓颉知识层**。

## 2. 目标与非目标

### 2.1 目标

| 编号 | 目标 | 可验收的判据 |
|---|---|---|
| G1 | 离线可查 | 断网环境下检索语言手册 / API / 示例 / 工程流程，命中率满足 §13.3 的用例集 |
| G2 | 按需加载 | 常驻 system prompt 增量 ≤ 400 token（只加"索引 + 用法说明"），正文命中后再 `read_file` |
| G3 | 生态对接 | 能收录 CangjieSkills / x2cj 等外部技能包（frontmatter 兼容映射），不重写其内容 |
| G4 | 可更新可追溯 | 语料带来源 / 版本 / 许可 / sha256；一条命令更新并可回滚 |
| G5 | 不破交付承诺 | 仍是单文件静态产物 + `~/.cjh` 数据目录，零新增运行时依赖 |

### 2.2 非目标

| 编号 | 非目标 | 说明 |
|---|---|---|
| N1 | 不做模型微调或权重侧知识注入 | 知识层是运行时检索，不碰训练 |
| N2 | 一期不引入向量检索 / 嵌入模型 | 无外部依赖约束；是否二期引入见 §15 |
| N3 | 不把语料编译进二进制 | 理由见 §4.2；除非评审明确要求"零数据文件"分发 |
| N4 | 不替代 `WebFetch` | 检索无命中时仍以官网兜底，两者是互补关系 |
| N5 | 不做语料全文常驻内存 | 索引常驻，正文按需读取 |

## 4. 关键约束

### 4.1 技能是"全文注入"，不能当语料容器

`loadSkills` 把所有技能**正文**拼进 system prompt（`:219-220`），并且 `enabled_skills` 白名单只能整体开关。若把官网 API 手册（数 MB）做成技能：每次请求都携带它，token 成本不可接受，prompt 缓存也被撑爆。

**结论**：语料走"**索引 + 检索工具 + 命中后 `read_file`**"；技能只放"流程 / 模板 / 用法说明"这类短文档，单篇建议 **≤ 2 KB**。

### 4.2 单文件静态产物：语料不打进二进制

当前交付承诺是静态单文件（v1.3.28 实测：Linux `dist/cjh-linux-x64` = 16,638,088 B，`ldd` 仅 6 项系统库；Windows exe = 13,716,480 B，导入表 7 个 DLL，stdx 静态链接进 exe）。若把语料编进二进制：

1. 需要仓颉的**编译期文件内嵌**能力——标准库是否有 `include_str!` 类设施**在实施前必须验证**；若没有，只能用构建脚本把语料生成巨型常量 `.cj` 文件（可行但丑，且编译期内存与编译时间上升）；
2. 二进制体积与启动内存线性上升，与 G5 冲突；
3. **语料更新 = 重新发版**，与 G4 冲突。

**结论**：语料作为**数据目录**随包分发或首次运行安装（§10 给两条路线与推荐）。

### 4.3 零新增运行时依赖 → 自建纯文本索引

仓颉侧没有 SQLite 类依赖，也不宜为此引入第三方库（项目规范：能独立的包要独立、职责单一、禁止把通用工具塞进业务包）。索引必须**自研且纯文本**（§6.3）：可随语料分发、可 diff、可人工 `read_file` 查看、可被测试直接断言。

### 4.4 语料的时效与许可

知识层的最大风险不是检索不到，而是**检索到过时或不合法的内容**并让模型自信作答。因此每条语料必须能回答三个问题：**哪来的**（来源 URL + 抓取时间）、**什么版本**（对齐仓颉 / cjh 版本）、**什么许可**（能否再分发）。这三项写入 `manifest.json`（§6.2），并作为 `cjh ref status` 的输出与测试断言项。

## 5. 总体设计

四层 + 一条闭环：

```text
┌─────────────────────────── cjh 运行时 ───────────────────────────┐
│ system prompt                                                    │
│   ├─ AGENTS.md（项目指令，已有）                                 │
│   ├─ 项目记忆段（已有：src/skills.cj:444）                        │
│   └─ 技能段（已有；新增内容一律是"短文档"）                        │
│        └─ 新增一行用法说明：「查仓颉 API / 手册 / 示例用 cangjie_ref」│
├──────────────────────────────────────────────────────────────────┤
│ 工具层（14 → 15）                                                 │
│   └─ 新增 cangjie_ref(query, scope?, limit?)   ← 只读 / 离线 / 无副作用│
│        └─ 命中：返回 文件路径 + 行号区间 + 片段（≤ N 行）          │
│             模型再 read_file 取全文（复用既有截断回溯约定）        │
├──────────────────────────────────────────────────────────────────┤
│ 资产层  ~/.cjh/cangjie-ref/                                       │
│   ├─ manifest.json   来源 / 版本 / 许可 / sha256                  │
│   ├─ docs/           语言手册、API 文档（Markdown）                │
│   ├─ examples/       示例代码（仓颉示例、官方示例仓等）            │
│   ├─ process/        环境搭建、中心仓发布、PR / README 模板        │
│   ├─ skills/         收录的外部技能包（CangjieSkills / x2cj，可选）│
│   └─ index/          postings.tsv / titles.tsv / stats.json        │
├──────────────────────────────────────────────────────────────────┤
│ 更新层  cjh ref update|verify|status（CLI）+ TUI /ref              │
└──────────────────────────────────────────────────────────────────┘
   闭环：检索命中 → （可选）结论写入项目记忆 → 下次会话直接可用
```

一次典型问答的数据流：

1. 用户问"仓颉里 `Byte` 数组怎么转 `String`？"
2. 模型按技能段里的用法说明调用 `cangjie_ref(query="Byte 数组 String 转换")`
3. 工具在 `index/` 中检索 → 返回 3 条候选（文件 + 行号区间 + 片段）
4. 模型用 `read_file` 取最相关文件的相关行区间 → 回答（并说明来源文件，便于核对）
5. （可选）把"整段 `safeFromUtf8` 解码，禁止逐字节 `String(Rune(byte))`"写入项目记忆，下次免检索

设计原则（与项目既有规范对齐）：

| 原则 | 本设计中的体现 |
|---|---|
| 单一职责 | 语料采集、索引构建、检索、更新四者分离；检索工具**只读**，下载只由 `cjh ref update` 负责 |
| 单向依赖 + 回调注入 | `CangjieRefTool` 只依赖 `cjutil`（UTF-8 / 文件工具）与本地索引，**不依赖** `cjh.agent`；需要 UI 反馈时通过回调注入，避免 `cjh.tools <-> cjh.agent` 循环 |
| 可复用工具函数集中 | UTF-8 安全解码、目录递归遍历等复用 `cjutil` / 既有 `grep`、`glob` 实现，**先查再写**，不重复定义 |
| 能独立的包要独立 | 候选做法：一期放 `src/tools/` 独立文件，稳定后若语料/索引能力对上层通用，再下沉为独立包（如 `cjref`），供生态复用 |
| 借鉴而非排斥 | 技能通道沿用 `~/.cjh/skills`；外部技能包只做 frontmatter 兼容映射，不另造格式 |

## 6. 数据布局、语料组织与索引格式

### 6.1 目录布局

```text
~/.cjh/cangjie-ref/
├── manifest.json          # 元数据：来源 / 版本 / 许可 / 校验
├── docs/                  # 语言手册、API 文档（Markdown，站内链接重写为本地相对路径）
├── examples/              # 示例代码（.cj，含可编译的最小工程骨架）
├── process/               # 流程与模板（环境搭建、中心仓发布、PR / README 模板）
├── skills/                # 收录的外部技能包（frontmatter 兼容，可选，三期）
├── index/
│   ├── docs.tsv           # docId -> relative/path
│   ├── postings.tsv       # 倒排：term -> docId:lineNo,docId:lineNo,...
│   ├── titles.tsv         # 标题行：docId,lineNo,level,title
│   └── stats.json         # 文档数 / 行数 / 词条数 / 构建时间 / 语料版本
└── cache/                 # 更新下载的临时包（成功即清空）
```

### 6.2 `manifest.json`（"可追溯"的落地载体）

```json
{
  "schema": 1,
  "corpus_version": "2026.09.1",
  "cjh_version": "v1.3.28",
  "cangjie_version": "1.0.5",
  "built_at": "2026-09-12T09:40:00+08:00",
  "index": { "docs": 42, "lines": 86000, "terms": 52000 },
  "sources": [
    {
      "name": "cangjie-lang 官方文档站",
      "url": "https://cangjie-lang.cn/",
      "fetched_at": "2026-09-12T09:35:00+08:00",
      "license": "见官网声明（实施前逐项核对）",
      "sha256": "…",
      "probe": "HTTP 200 / 191,468 B（2026-09-12 实测）"
    },
    {
      "name": "AtomGit Cangjie 组织与语料仓",
      "url": "https://atomgit.com/Cangjie",
      "fetched_at": "2026-09-12T09:35:00+08:00",
      "license": "见仓库声明（实施前逐项核对）",
      "sha256": "…",
      "probe": "组织页 200 / 271,224 B；CangjieCorpus 200 / 225,000 B（此前偶发 418，需重试）"
    }
  ],
  "files": [ { "path": "docs/api/std-string.md", "sha256": "…", "lines": 812 } ]
}
```

- `cangjie_version` / `cjh_version` 用于**知识时效**声明：检索结果附带版本，模型回答时可说明依据（对应 §4.4）。
- `sources[].license` 为必填项；**未确认许可的语料一律不收录**（宁缺勿滥）。
- `probe` 记录**来源可用性实测**，不是可选装饰：2026-09-12 实测发现 `https://cangjie-lang.cn/api.html` 返回 **500**（不可用）、`https://pkg.cangjie-lang.cn/` 仅 1,028 B（SPA 壳页面，正文需另找数据接口）。
- 由此得出一条语料采集原则：**官方站点是 SPA 时，优先抓官方 Markdown 源仓（AtomGit / GitCode）而非解析 HTML**；HTML 只作为"入口发现"手段，不作为语料本体。抓取失败（如偶发 418 反爬）必须有重试与回退策略，并把最终抓取时间写回 `fetched_at`。

### 6.3 索引格式（纯文本、可 diff、可人工查看）

| 设计点 | 方案 | 理由 |
|---|---|---|
| term 归一化 | ASCII 小写；标识符按 `_` / `.` / `::` / 驼峰切分（`StringBuilder.appendSafe` → `stringbuilder`、`appendsafe`、`append`、`safe`）；CJK 按 **2-gram**（"函数重载" → `函数`、`数重`、`重载`） | 中文不引入分词词典（零依赖，符合 §4.3）；2-gram 对短查询召回足够 |
| postings 行格式 | `term \t docId \t lineNo1,lineNo2,...`（行号升序去重，term 升序） | 升序 + 二分可做 query 多 term 的合并扫描；纯文本可 `read_file` 检查 |
| 路径存放 | 独立 `docs.tsv` 做 `docId -> path` 映射 | 避免路径字符串在 postings 里重复膨胀 |
| 粒度 | **行级**倒排（只记命中行号），不建全文索引 | 片段由命中行号现读文件得到（复用既有 UTF-8 安全切片），索引体积可控 |
| 体积 / 耗时目标 | 语料 5 MB 级 → 索引 ≤ 1 MB；构建 < 3 s（单线程足够） | 保证"首次安装"体验与仓库体积 |

### 6.4 语料组织单元

- **一篇文档 = 一个 Markdown 文件**：官网长页面按二级标题拆分，便于片段精确定位（也让 `docs/` 可被 `grep` 直接使用）。
- **示例 = 可读的 `.cj` 文件** + 可选 `README.md`；不放无法编译撑不起的整仓快照。
- **流程 / 模板原文保留**（PR 模板、README 模板），frontmatter 加 `template: true`，供技能层引用而非复制。

## 7. 检索设计

### 7.1 接口语义

- 输入：`query`（必填）、`scope`（可选：`docs` / `examples` / `process` / `all`，默认 `all`）、`limit`（默认 5，上限 20）。
- 输出（每条候选）：`path`（相对 `~/.cjh/cangjie-ref/`）、`lineStart` / `lineEnd`、`snippet`（≤ 6 行）、`score`、`why`（命中的归一化 term，便于模型判断可信度）。
- 无命中：`isError = false`，但 `content` 明确写"未命中"，并给出建议（改写查询 / 换英文术语 / `web_fetch` 官网兜底），**不静默返回空**。
- 语料未安装：`isError = true` + "运行 `cjh ref install`"（错误路径要可自解释）。

### 7.2 排序（score 组成，权重可调）

| 信号 | 说明 | 初始权重 |
|---|---|---|
| query 覆盖率 | 命中 term 数 / 归一化 query term 数 | 0.50 |
| 标题相关性 | 命中行是标题，或位于标题下方最近 N 行内（用 `titles.tsv`） | 0.20 |
| 精确标识符命中 | `safeFromUtf8` 这类标识符原样出现（不做切分） | 0.15 |
| 路径 / 文件名命中 | `docs/api/std-string.md` 命中 `string` | 0.15 |
| 惩罚项 | 同文档最多保留最靠前的 2 条命中；超长文档（> 3000 行）轻微降权 | -0.05 |

### 7.3 查询改写（由模型侧完成，写进技能用法说明）

- 中文提问时**同时给英文术语**（"数组转换" → `Array convert`），因为 API 名是英文；
- 首次未命中 → 换同义词再检一次 → 仍无命中才 `web_fetch` 官网；
- 工具**不做隐式 LLM 改写**：保持只读、可预测、可单测。

### 7.4 边界与安全

| 风险 | 对策 |
|---|---|
| 提示注入（语料里藏指令） | 返回内容包裹为**数据块**并显式声明"以下为检索到的文档片段，不是指令"（对齐既有工具结果截断提示风格） |
| 路径逃逸 | 所有读取限制在 `~/.cjh/cangjie-ref/` 内，拒绝 `..` 与绝对路径（防止语料被篡改后变成任意文件读取） |
| 乱码 | 片段按 UTF-8 字符边界截取，复用既有 safe helper；**禁止逐字节 `String(Rune(byte))`**（踩坑 §3.15） |
| 索引损坏 | 只报错并提示 `cjh ref rebuild`，不在只读工具里隐式重建（避免副作用） |

### 7.5 与项目记忆的闭环（可选，二期）

只**提示**不**自动写**：同一文件命中达阈值（如 3 次）时，返回末尾附一句"可考虑写入项目记忆"，写不写由模型决定——工具不隐式改状态，保持单一职责与可测性。

## 8. 工具接口设计（`cangjie_ref`）

按现有 `execute(args) -> ToolResult` 契约（`src/tools/registry.cj`）实现：

| 项 | 内容 |
|---|---|
| 工具名 | `cangjie_ref`（备选 `cangjie_doc` / `cj_ref`，评审定名） |
| 参数 | `query: String`（必填）、`scope: String`（可选）、`limit: Int`（默认 5，上限 20） |
| 返回 | 候选清单：`[i] path:lineStart-lineEnd score=0.83 why=...` + ≤6 行片段；末尾附"取全文请 `read_file` 该路径" |
| 错误路径 | 语料未安装 / 索引缺失 / 索引损坏 / `query` 为空——四种都必须给可执行建议，不抛裸异常 |
| 只读性 | 不写盘、不发网络请求、不改状态 |
| 文案单一来源 | 工具 `description` 与技能段里的用法说明**同源**（避免两处文案漂移） |
| 依赖方向 | `CangjieRefTool`（`cjh.tools`）→ `cjutil`（UTF-8 / 文件工具）+ 本地索引读取；**不依赖** `cjh.agent`（对齐"单向依赖 + 回调注入"） |
| 与 `grep` / `glob` 分工 | 检索**只在索引上**做（term → 行号）；全文正则仍交既有 `grep`。工具描述里写明分工，避免模型误用 |
| 测试 | 走 `execute(args)` 断言 `ToolResult`：主路径 / 空 query / 语料未安装 / 越界路径（§13） |

### 9.1 外部技能包实测：CangjieSkills（2026-09-12 核实）

来源 `https://atomgit.com/Cangjie-SIG/CangjieSkills`，`git clone --depth 1`（分支 `cangjie-1.0.5`）实测：

| 项 | 实测值 |
|---|---|
| 规模 | 7,822 文件（`.md` **7,577**、`.py` 76）；去除 `.git` 后总体积 **50 MB** |
| 语料 | `references/` = **39 MB** Markdown；结构为"主题索引 → 细分索引 / API 成员表 → 叶子契约与示例"的**渐进披露** |
| 技能数 | **3 个**：`cangjie-coding`（语言 / 标准库 / 工具链知识库）、`cangjie-code-review`（审查、性能与 OOM / RSS 取证）、`cangjie-build-diagnose`（cjc / cjpm 报错与运行时故障诊断） |

| 佐证 | 本机 AtomCode 环境已安装 `cangjie-coding`（描述逐字一致），属成熟在用发布件，非实验品 |

**对设计的三个结论**：

1. **它已是本设计二期的成熟实现**（技能入口 + 39 MB 语料 + 查询后端 + `e2etests` + `build.py`）。自采官网文档做二期 = 重复劳动（且官网是 SPA、`api.html` 实测 500）。→ **二期主语料源改为收录 CangjieSkills**（`references/` + 三个 `SKILL.md`），cjh 只补它缺的"零依赖本地检索 + 与 TUI / 项目记忆的深度集成"。
2. **形态需映射**：cjh 技能是**扁平** `~/.cjh/skills/<name>.md`（`src/skills.cj:6`；`:158 Directory.walk` 非递归，只扫直接子项），它是目录式 → 安装映射为：三个 `SKILL.md` → `~/.cjh/skills/<name>.md`；各技能 `references/` → `~/.cjh/cangjie-ref/skills/<name>/`（**保留原目录结构**以维持渐进披露语义）。

打包坑：`.agents/skills/cangjie-coding/`（8.7 MB）自带一份**发布态语料副本**，与 `references/` 内容重复，收录时必须去重（只取一处，索引指向同一份内容）。

## 10. 分发与打包

### 10.1 两条路线

| 路线 | 做法 | 优点 | 代价 | 取舍 |
|---|---|---|---|---|
| A 随包分发 | 发布产物（`dist/*.tar.gz`、`*-selfcontained.zip`）内附 `data/cangjie-ref/` + `data/skills/`，首启或 `cjh ref install` 解包到 `~/.cjh/` | 离线开箱即用；语料与二进制版本严格对齐 | 发布产物体积增加（预计压缩后 ~1 MB） | **推荐基线**（核心流程 / 模板 < 1 MB 可无条件内置） |
| B 首次运行安装 | 首次使用走 `cjh ref update` 从 AtomGit 拉取 | 产物体积不变 | 首装需联网，与"离线可用"目标冲突 | 只作为**增量更新**通道，不作首装唯一来源 |

两条路线共用同一份 `manifest.json`，因此"随包"与"更新"在实现上是同一段解包 + 校验代码。

### 10.2 打包内容与体积预算

| 组件 | 内容 | 压缩前 | 压缩后（估） |
|---|---|---|---|
| `skills/`（一期六篇） | 流程 / 模板 / 速查 | ≤ 10 KB | ≤ 4 KB |
| `docs/`（核心子集） | 语言速查 + 常用标准库 API（String / Array / Option / Mutex / io / fs 等） | 1~2 MB | 0.3~0.6 MB |
| `process/` | 环境搭建 / 中心仓发布 / PR / README 模板 | ≤ 50 KB | ≤ 20 KB |
| `examples/` | 精选示例（每例可编译） | 0.5~1 MB | 0.2~0.4 MB |
| `index/` | 倒排 + 标题 + 映射 | ≤ 1 MB | ≤ 0.3 MB |
| **合计** | — | ~3~4 MB | **~0.8~1.3 MB** |

若全量语料（整站手册 + 全示例仓）超过 10 MB，拆成"**内置核心**（默认，上表）+ **可选全量**（`cjh ref update --full`）"。

**实测修正（2026-09-12）**：全量语料若取 CangjieSkills，其 `references/` 单仓即 **39 MB**（未压缩），远超上表"全量 >10 MB"的估算。因此：

- "核心随包"必须**只挑主题索引 + 高频标准库**（目标压缩后 ≤ 1 MB），全量一律走 `--full`（39 MB 级下载，需进度显示、超时与重试控制）；
- 索引体积目标（39 MB 语料的行级倒排初估 5~10 MB）需实测回填；若超预算，改为"**分片索引 + 按需加载**"（按技能 / 主题分片，只加载命中分片）；
- 收录 CangjieSkills 时注意其 `.agents/skills/cangjie-coding/` 与 `references/` 的内容重复（见 §9.1）。

**一期已落地的分发形态（2026-09-12 实测）**：一期**不改打包流程、不动二进制**——技能作为**仓内源目录 `skills/`**，由 `scripts/install-cangjie-knowledge.sh` 投影安装到数据目录，cjh 运行时读取。投影规则＝**入口与全文分离**：

| 位置 | 内容 | 是否进 system prompt |
|---|---|---|
| `~/.cjh/skills/<name>.md` | 短入口：frontmatter（name + description）+ 一行指向全文的**绝对路径** | ✅ 常驻（9 篇合计 6,588 B） |
| `~/.cjh/cangjie-ref/skills/<name>/SKILL.md` | 全文（命令 / 示例 / 清单） | ❌ 不常驻，模型按需 `read_file` / `grep` |

实测证据：全仓 `cjpm.toml` 无 `resource` / `embed` 声明（命中 0）；本批交付零 `.cj` / `cjpm.toml` 改动（`git diff HEAD --numstat` 为 0）；Linux 发布产物 **16,638,088 B 不变**，`dist/cjh-v1.3.28-linux-x64.tar.gz` 内仍只有 1 个文件。**"随包分发"（§10.1 路线 A）推迟到二期**；届时若在发布包内附 `data/skills/`，需把发布产物体积一并纳入发布检查清单（见 §15）。

### 10.3 对既有打包脚本的影响

- `scripts/winbuild.sh` 只做交叉编译（临时改 / 还原 `cjpm.toml`），**不涉及语料**；语料打包发生在发行步骤（把 `cangjie-ref/` 放进 zip / tar.gz 的同级 `data/` 目录）。
- `scripts/test.sh` 与语料无关；但**索引器必须能被单测直接驱动**（不依赖真语料，用 `/tmp/cjh_ut_*` 造小语料）。
- 复用 v1.3.28 的教训：`dist/*.zip` 与 `dist/windows-v*/` 在 `.gitignore` 中，新产物需 `git add -f`（或改写 `.gitignore` 否定规则）；语料若进 dist 同理。

### 10.4 首启安装的幂等与权限

- 安装 = 解包到 `cache/staging/` → 校验 `manifest.json` 的 `files[].sha256` → 原子 `rename` 到 `~/.cjh/cangjie-ref/`；失败回滚，不留半成品。
- 幂等：已存在且版本一致则跳过；版本更新走 §11 同一路径（同一份代码，两条入口）。
- 权限：只写 `~/.cjh` 下自建文件，不需要提权；Windows 对应 `%USERPROFILE%\.cjh\cangjie-ref\`。

## 11. 更新流程与信任链

### 11.1 CLI 与 TUI

| 命令 | 语义 |
|---|---|
| `cjh ref status` | 语料版本、`cangjie_version`、文档 / 行数 / 词条数、来源与许可清单、上次更新时间 |
| `cjh ref verify` | 按 `manifest.json` 逐文件校验 sha256，并做索引自检（term 升序、行号合法、docId 有映射） |
| `cjh ref update [--full]` | 拉取 → 校验 → 原子替换 → 重建索引 → 输出变更摘要（新增 / 修改 / 删除文档数） |
| `cjh ref rebuild` | 只用本地语料重建索引（语料未变而索引损坏时用） |
| TUI `/ref` | 交互式状态、检索试跑、更新确认（风格对齐既有 `/skills`、`/trust`） |

### 11.2 更新流程（原子 + 可回滚）

1. 读本地 `manifest.json` → 请求远端 `latest.json`（含 `corpus_version` + 包 URL + sha256）；
2. 版本相同 → 结束（"已是最新"）；
3. 下载到 `cache/`（超时 / 大小上限可控）→ **校验整包 sha256**；
4. 解包到 `cache/staging/` → 校验 `files[].sha256` 全覆盖（缺失即失败）；
5. `rename` 正式目录为 `cangjie-ref.old` → `rename` staging 为正式 → 成功删 `.old`；任一步失败则回滚；
6. 重建索引 → `cjh ref verify` → 打印摘要。

### 11.3 信任链复用（不另造轮子）

- 语料包安装**复用 V3 信任链**（`src/tools/trust.cj`、`~/.cjh/trusted-publishers`）：只有可信发布者签名的包自动安装，否则要求用户显式确认——与工具 / 插件审批使用同一套用户语言。
- 语料是**数据**：安装后不执行语料内任何代码（示例只读展示、不自动运行）；这条要同时写进文档与工具 `description`。
- 供应链最小化：远端只需 `latest.json` + 一个 tar.gz（可选签名），不引入包管理器依赖。

## 12. Token 与性能预算

| 指标 | 目标 | 手段 |
|---|---|---|
| system prompt 增量 | **≤ 400 token** | 技能段只含六篇短文档（≤ 10 KB）+ 一行 `cangjie_ref` 用法说明；**不注入语料** |
| 单次检索返回 | ≤ 5 条 × ≤ 6 行（≈ 600 token） | `limit` 默认 5、上限 20；片段行数硬上限 |
| 检索延迟 | P99 < 100 ms（索引 ≤ 1 MB） | 索引常驻内存（term → postings），命中行现读文件 |
| 常驻内存增量 | < 8 MB | 只加载索引（~1 MB） |
| 索引构建 | < 3 s（5 MB 语料，单线程） | 一次性任务，`cjh ref rebuild` 触发 |
| 磁盘占用 | 核心语料压缩后 ~1 MB + 索引 ≤ 1 MB | 全量走 `--full` 可选下载 |
| 离线保证 | 检索 + `read_file` 全程不需网络 | `cjh ref update` 是唯一联网入口 |

补充：检索返回**片段**而非全文，不把长文本塞进会话历史（复用既有工具结果截断 / 回溯约定），避免上下文膨胀。
