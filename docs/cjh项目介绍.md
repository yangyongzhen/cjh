# 仓颉语言原生 Coding Agent：cjh，一个文件就是整个开发团队

**GitHub: https://github.com/yangyongzhen/cjh**

---

## 它是什么

cjh 是一个用**华为仓颉语言从零实现**的交互式编码代理（coding agent harness）。在终端里用自然语言描述任务，Agent 自主规划、调用工具、观察结果、迭代直到完成——全程 TUI 实时呈现，也可以通过 Web 远程驱动。

但它不是又一个"LLM 套壳"。cjh 从立项起就给自己立了两条硬性指标：

> **省 token + 高执行效率**——每一项设计都围绕这两条展开。

---

## 为什么值得你关注

### 1. 单二进制零依赖：一个文件 = 一个 Agent

仓颉 `cjnative` 静态编译，产物是一个**零依赖的单文件可执行程序**——不需要 Python、不需要 Node、不需要任何运行时环境。下载即用，拷到任何 Linux 机器上直接跑。

| 平台 | 产物 | 依赖 |
|---|---|---|
| Linux | 单文件（15.8MB） | 仅系统 libc |
| Windows | exe + 2 个运行时 DLL（4.8MB zip） | 仅系统库 + 仓颉运行时 |

跨平台不靠解释器，靠的是仓颉**多后端编译 + 终端层平台抽象**（termios / Win32 条件编译，一份源码多平台二进制）。

### 2. 省 token 是工程化指标，不是口号

LLM 按 token 计费，coding agent 多轮工具调用 token 消耗惊人。cjh 从四个维度系统化优化：

- **工具结果截断与回溯**：超长结果保留头尾 + 中间落盘，完整内容可回溯，不丢失中间信息
- **自动 Compaction**：上下文超阈值自动 LLM 摘要压缩，实测 prompt 峰值从 42.9K → 9.4K tokens
- **Prompt Cache 利用**：缓存前缀命中，DeepSeek 实测命中率显著
- **Hashline 文件改写**：行号锚点 + 内容验证的精准行级编辑，避免整文件重写

### 3. 高执行效率：工具并行 + 持久会话

- **V2d 并发执行引擎**：工具调用自动做 DAG 依赖分析，无依赖的工具并行执行
- **持久 bash 会话**：跨命令保留 cwd 和环境，不用每次重建
- **Provider 连接预热**：流式响应首包延迟显著降低

### 4. 安全 DNA：语言层安全 + 信任链双保险

仓颉的类型系统与内存安全从**语言层面**降低恶意代码风险；插件系统叠加 **SHA256 校验和 + SM2 国密签名验证**（仓颉 `stdx.crypto` 原生实现，零外部依赖）——插件安全是"编译期类型检查 + 信任链验证"双保险。

### 5. 三域 capability 安全模型

命令 / 工具 / 资源三个域的白名单 + 危险操作审批链，默认宽松、声明即严格——可控的执行边界。

### 6. 完整可用的产品形态

- **TUI 全屏界面**：差分渲染、6 套主题、多行编辑器、鼠标支持、粘贴安全
- **Web 远程驱动**：内置 HTTP Server + WebSocket 流式对话 + REST API + 前端 SPA，远程驱动 Agent
- **工作区管理**：多项目注册 + 运行时切换（chdir 真正生效，无需重启）
- **多 Provider 开箱即用**：OpenAI / DeepSeek / GLM / Anthropic / Ollama，`/provider` 热切换
- **MCP 协议**：仓颉语言首个 MCP 客户端实现，接入工具网络
- **技能系统**：Markdown 即技能，声明式加载

### 7. 面向未来的多 agent 并行编排

多 agent 协作是业界成熟范式（OpenAI Swarm 的 handoff 串行交接等）。cjh 借鉴该范式、选择**并行子代理 + 上下文隔离**的取向：

> 省 token 是分工并行的核心目标，而非副产品。团队协作的常识是每个人只需知道自己职责相关的部分——子代理按任务隔离上下文，目标是**同样的任务、更少的 token**。这与 handoff 串行（历史持续累积）形成本质区别：后者提升吞吐，前者同时优化成本。

由仓颉 M:N 轻量线程支撑——子代理即进程内线程，调度零开销；整个多代理系统仍是一个文件。（V4 规划中，`task` 工具已建 explore/worker 基础）

开发 cjh 沉淀出的资产，不是硬凑的贡献——全部**零依赖或仅官方 stdx**，可独立发布：

| 库 | 定位 |

| **cjutil** | 工具库（SHA-256/SM2/UTF-8/网页提取/BM25/JSON 修复/SSRF） |
| **cjllm** | LLM 协议库（OpenAI/Anthropic/Ollama/Mock） |

这些库是仓颉生态在 AI 编程领域的**旗舰实践**——仓颉能做什么，看 cjh 就知道。

## 快速上手

```bash
# Linux：下载单文件直接跑
./cjh-v1.3.2-linux-x64

# 首次配置
mkdir -p ~/.cjh && echo '{"api_key": "sk-xxx"}' > ~/.cjh/auth.json

# 或源码构建（需仓颉 SDK 1.0.5+）
git clone https://github.com/yangyongzhen/cjh
cd cjh && source cj-env.sh && cjpm build
```

**从源码到可用的完整质量保障**：238 个单元测试全绿 + 36 个 PTY 真实终端集成测试——每项能力都有测试兜底，不是演示级项目。

## 结语

cjh 的价值不在于"又一个 agent"，而在于证明了：**仓颉语言做 coding agent，不是"用仓颉写一遍"的重复，而是单二进制、安全 DNA、原生并发、国密加密、多后端跨平台这些特性组合出来的真实优势**。

如果你的项目也受困于运行时依赖、token 成本、执行效率或插件安全——cjh 给出了一个仓颉原生的完整答案。
