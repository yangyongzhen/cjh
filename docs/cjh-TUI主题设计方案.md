# cjh TUI 主题设计方案：星霜青配色体系

> 最后更新：2026-08-24
> 性质：TUI 配色规范与实施依据
> 目标：给仓颉语言配套的终端 AI Agent 做 TUI 配色，不要选普通亮青作为主色，优先选用「鸿蒙生态同源的星霜青」作为品牌主色，搭配「素白、深炭灰、浅琥珀」做分层辅助色。

---

## 一、为什么普通亮青不适合作为仓颉 Agent 的主色

高饱和度的亮青存在三个明显的适配硬伤：

1. **和仓颉的品牌调性完全割裂**：普通亮青是通用赛博风配色，没有任何品牌记忆点，和仓颉语言原生绑定的鸿蒙 / OpenHarmony 技术生态没有视觉关联，用户看到配色无法第一时间联想到这是仓颉专属的编程 Agent。
2. **终端长时间使用易视觉疲劳**：高亮的高饱和青在终端深色背景下明度刺目，代码审查、长会话调试这类动辄 1-2 小时的长时间使用场景下，人眼很容易产生视觉酸痛，不符合编程工具的长时间使用要求。
3. **代码语义分层辨识度差**：纯亮青很难做出层次感，关键字、注释、报错、调试信息用同色系亮青区分度极低，搭配 LSP 语义高亮、DAP 调试栈展示的时候，很难快速把错误状态和普通信息用色彩区分开。

---

## 二、「星霜青」主色的核心适配优势

星霜青是低饱和度、带冷灰调的雾面青色，也是鸿蒙生态系统工具的御用品牌色，刚好完美匹配仓颉语言的所有特性：

1. **品牌强关联，用户心智统一**：仓颉是华为推出的鸿蒙原生编程语言，星霜青和鸿蒙 PC、OpenHarmony 系统工具的配色体系完全同源，开发者打开 Agent 的瞬间就能通过色彩感知到这是原生适配仓颉的专属工具，不需要额外引导就能建立品牌认知，和生态其他工具的视觉风格完全统一。
2. **长时间终端使用零视觉负担**：低饱和雾面青在深色 TUI 背景下，明暗对比刚好达到 WCAG 无障碍可读性标准，既不会像亮青那样刺眼，也不会因为明度太低导致看不清，完全适配 omp 这类工具里并行子 Agent 状态监控、长代码上下文浏览、DAP 调试栈逐行查看这类长时间高频使用场景。
3. **仓颉代码语义分层友好**：星霜青可以通过透明度变化轻松做出至少 5 层同色系深浅区分，刚好可以对应仓颉的类名、函数名、关键字、导入路径、模块名的 LSP 语义高亮层级，搭配后续可以接入的 ast-grep 结构化查询结果展示，语义区分度远高于纯亮青。
4. **跨终端渲染一致性强**：omp 底层是纯 Rust 原生实现，跨 macOS / Linux / Windows / 鸿蒙四大平台运行，星霜青这类低饱和色在不同终端的色彩管理模式下渲染偏差极小，不会出现部分终端里偏蓝、部分终端里偏绿的显示错乱问题，完全符合 omp 全平台行为一致的核心设计理念。

## 三、完整配套配色方案，适配全场景交互

围绕星霜青主色搭配辅助色，覆盖 TUI 里所有交互状态，完全匹配仓颉 Agent 的功能场景：

| 层级 | 色名 | 用途 | 配色逻辑 |
|------|------|------|----------|
| **品牌主色** | 星霜青 | 模型徽章、标题栏、输入提示 ❯、工具调用名 | 低饱和雾面青，鸿蒙同源品牌色 |
| **背景层** | 深炭灰 | TUI 背景（比纯黑柔和） | `#1A1F26`，长时间看不干涩 |
| **基础文本层** | 素白 | 普通代码、说明文本、回复正文 | `#E8EAEF`，对比度 7:1 满足无障碍 |
| **高亮交互色** | 浅琥珀 | 选中行、待确认编辑预览、状态栏边框 | 暖色不与主色冲突，抓注意力 |
| **报错色** | 低饱和暖红 | 错误、崩溃栈、P0 审查问题 | 柔和不刺眼，不制造焦虑 |
| **次要信息色** | 淡灰蓝 | 后台状态、加载提示、非核心信息 | 低存在感，不抢占主内容注意力 |
| **成功色** | 低饱和绿 | 任务完成、就绪徽章、流式指示 | 与报错色形成明确正负反馈 |
| **静音色** | 中灰 | 分隔线、参数灰、次要文本 | 次要信息的统一灰度 |

## 四、cjh TUI 实施映射（ANSI 256 色彩空间）

cjh 当前 TUI 配色基于 ANSI 256 色彩空间（`Ansi.fg(code)`），本方案在该色彩空间内选取最接近目标色相的色码：

| 角色 | 常量名 | 色码 | 色名 | 替代前 |
|------|--------|------|------|--------|
| 品牌主色 | `THEME_ACCENT` | 73 | 星霜青（雾面青绿灰） | 原 51 亮青 |
| 成功色 | `THEME_OK` | 108 | 低饱和鼠尾草绿 | 原 82 亮绿 |
| 警告色 | `THEME_WARN` | 179 | 浅琥珀金 | 原 226 亮黄 |
| 错误色 | `THEME_ERR` | 167 | 低饱和暖红 | 原 196 高饱和红 |
| 静音色 | `THEME_MUTED` | 245 | 中性灰 | 原 240 暗灰 |
| 次要信息色 | `THEME_INFO` | 103 | 淡灰蓝 | 新增 |
| 高亮交互色 | `THEME_HIGHLIGHT` | 179 | 浅琥珀金（与警告色共享色码） | 新增 |
| 品牌辅色 | `THEME_PRIMARY` | 67 | 雾面深青蓝（鸿蒙蓝灰调） | 原 33 华为蓝 |
| 基础文本 | `COLOR_TEXT` | 254 | 素白 | 新增（原 15 纯白） |
| 背景 | `COLOR_BG` | 235 | 深炭灰 | 新增（暂未启用背景色，预留） |

### 4.1 色码选取理由（256 色彩空间近似）

- **星霜青 = 73**：256 色里 73 号是低饱和青绿带灰调，肉眼观感接近鸿蒙 DevEco 工具的主色，明度适中不刺眼，长时间盯着看不会酸痛。
- **低饱和暖红 = 167**：比 196 高饱和红柔和很多，偏向砖红 / 暗珊瑚，错误提示醒目但不制造焦虑感。
- **浅琥珀金 = 179**：暖色系金黄偏琥珀，作为选中行 / 边框高亮时能和星霜青主色形成冷暖对比，视觉层级清晰。
- **淡灰蓝 = 103**：低饱和蓝灰，作为"后台运行中"这类次要状态色，存在感弱但可辨识，不抢主内容注意力。
- **雾面深青蓝 = 67**：比主色更暗一档的同色系，用于标题栏 / 品牌辅色，和主色形成同色系两层深浅，呼应"星霜青 5 层深浅"设计。

### 4.2 状态栏边框配色调整

原状态栏边框 `+--`、`->`、`+` 为静音灰，上一轮改成 `COLOR_BLUE`（39）高饱和蓝。

按本方案，边框应改为 **浅琥珀金 `THEME_WARN`（179）**：暖色与主色形成冷暖对比，作为"输入框位置"的视觉锚点比蓝色更醒目，且和选中行 / 预览卡片高亮统一为同一交互色，视觉系统更一致。

## 六、设计原则总结

1. **品牌同源**：星霜青 = 鸿蒙生态御用色，仓颉 = 鸿蒙原生语言，色彩心智天然统一。
2. **长时间可用**：全色系低饱和，明暗对比满足 WCAG，1-2 小时编码审查零视觉负担。
3. **语义分层友好**：星霜青同色系 5 层深浅对应 LSP 语义高亮，冷暖对比（青主色 + 琥珀交互色）让状态层级一眼可辨。
4. **跨终端一致**：低饱和色在不同终端色彩管理下渲染偏差极小，macOS / Linux / Windows / 鸿蒙四平台显示统一。
5. **迁移成本零**：配色逻辑完全匹配 omp / Cursor / Claude 等主流 AI 编程工具，用户迁移无需重新适应。
